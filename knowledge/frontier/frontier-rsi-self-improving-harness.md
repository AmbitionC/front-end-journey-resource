RSI 是 Recursive Self-Improvement 的缩写，意思是递归自我改进：让 Agent 自己找出自己哪里做得不好，自己动手改，改完再接着改。2026 年 9 月到 11 月，这个方向集中出了一批论文和基准。本期把它讲清楚：现在说的 RSI 改的到底是什么，怎么保证越改越好而不是越改越偏，目前实际能做到什么程度。

> **本期 30 秒版**
> 1. 现在的 RSI 主要改 Harness，不改模型：模型权重冻结，Agent 改的是包在模型外面的提示词、工具、上下文管理和控制流程。一篇 11 月的论文把它归纳成「诊断、提案、验证、部署」四步循环。
> 2. 最大的风险是过拟合和越改越臃肿：Google 的 RRSI 给自我改进加了「正则化」，在没见过的 5 个基准上最多提升 4.3 分，同时比不加约束的做法少用 30% 的 token。
> 3. 效果是真的，但很看模型也很花钱：Flex-RSI 基准测了 18 个模型，自我改进在 Agent 需要自己搭方案的任务上帮助最大，开源模型明显落后。

## 先弄清楚：RSI 改的是什么

一个 Agent 可以改的东西，从轻到重大致有这几层：

| 改的对象 | 例子 | 现在的 RSI 论文 |
| --- | --- | --- |
| 提示词 | 改系统提示词里的一句话 | 都包含 |
| 上下文和记忆 | 什么信息进上下文、怎么压缩 | 都包含 |
| 工具和流程 | 新增工具、调整控制循环 | 都包含 |
| Harness 代码 | 直接改外壳的源代码 | 主流做法 |
| 模型权重 | 自己造数据、自己微调 | 少数，如 RSI-Env |

「递归」体现在两处：一是改完的版本接着负责下一轮改进；二是负责改进的那部分（改进器）本身也在可以被改的范围里。

## 1. 一个统一框架：诊断、提案、验证、部署

**发生了什么**

Google 的两位作者 2026 年 11 月 17 日发了一篇论文 [Harnesses That Improve Themselves](https://arxiv.org/abs/2611.22299)，把已有的十几个自我改进系统放进同一个框架里。论文明确说，讨论范围是模型权重不动、只让 Harness 自己演化。

框架有两部分。Harness 里可以被改的有四块：上下文与状态、Agent 控制、动作接口、验证与恢复。改的过程是一个四步的外循环：

1. **诊断**：从失败的运行记录里找出问题。
2. **提案**：生成代码补丁。
3. **验证**：候选版本要过一道闸门，改过的代码路径确实跑到了，并且在留出的验证集上没有退步。
4. **部署**：通过才合入，一次只改一个模块。

论文还强调，评分脚本要放在 Agent 沙箱之外的只读存储里，Agent 碰不到。

**论文自己的实验**

在 SWE-bench Lite 的 60 个任务上，干活的模型是冻结的 Gemini 3.8 Flash：

| 做法 | 解决率 | 每个任务的 token |
| --- | --- | --- |
| 初始 Harness | 5.0% | 114.8k |
| 只反思改提示词 | 2.5% | 60.5k |
| 不加约束地重写 | 42.5% | 451.6k |
| 按模块改、过闸门才合入 | 40.0% | 46.7k |

最后两行是重点：不加约束地重写分数略高，但 token 用量是按模块改的近 10 倍。论文也说明了局限：每个子集只有 20 个任务，只测了一个基准和一个模型家族。

**和以前有什么不同**

以前说 Agent 的「自我改进」，多半指反思：做错了，把教训写进提示词或记忆。这个框架里，只改提示词是最弱的一档，在这组实验里甚至比不改还差。真正起作用的是改 Harness 的代码，并且每次改动都要过一道独立的验证。

**面试里怎么用**

被问「你了解 RSI 吗」或「Agent 怎么做自我改进」时：

> 现在说的 RSI 主要是 Harness 层面的：模型权重不动，让 Agent 改自己外面那层的提示词、工具、上下文管理和控制流程。标准流程是四步，从失败记录里诊断问题，生成补丁，在留出的验证集上确认没有退步，通过才合入，而且一次只改一个模块方便回退。关键的工程约束是评分脚本和验证数据必须放在 Agent 碰不到的地方，否则它会去改评分而不是改自己。

**对应知识点**：[从零构建 Agent 运行时](https://www.agent-journey.cn/knowledge?activeKey=build-agent-framework)、[线上反馈、评估集与持续改进闭环](https://www.agent-journey.cn/knowledge?activeKey=agent-feedback-loop)、[Agent 评测原理：任务、轨迹与环境结果](https://www.agent-journey.cn/knowledge?activeKey=agent-eval-framework)

## 2. RRSI 和自我改进记忆：怎么防止越改越偏

**发生了什么**

自我改进最常见的毛病是过拟合：Harness 在用来改进的那批任务上分数越来越高，换一批任务就不行了，同时外壳越堆越复杂。两篇 Google 的论文分别处理这个问题的两面。

**RRSI：给改进过程加正则化**

[RRSI](https://arxiv.org/abs/2609.24972)（Google Cloud AI Research 等，arXiv 2026-09-21，[代码已开源](https://github.com/google-research/rrsi)）借用了机器学习里正则化的思路，在提案和筛选两头加约束：

- 提案一侧有改动预算，越往后可改的幅度越小，并且鼓励去试没探索过的方向。
- 筛选一侧有四道关：一个评审专门拦掉只针对某个基准的改动；分数提升要超过噪声带才算数，噪声带是把没改过的 Harness 重复跑几次量出来的；提升要配得上增加的成本；最后有一个修剪器，把测不出正收益的部件删掉。

论文摘要给的结果：在用来改进的那批任务上最多提升 6.0 分，在搜索过程从没见过的 5 个基准上最多提升 4.3 分，同时比不加正则的改进少用 30% 的策略 token。

**自我改进记忆：换了模型或任务，经验怎么带过去**

[Self-Improvement Memory](https://arxiv.org/abs/2611.18856)（Google Cloud AI、Google DeepMind、宾州州立大学，2026 年 11 月）研究的是另一个现实问题：基准换了、底层模型升级了，之前改进的成果怎么延续。

它的做法是给负责改进的那一方配一份记忆，按「根因假设」把历次改动归组，记下当时的理由、预期结果和实际结果。注意这份记忆是给改进器看的，不是给干活的 Agent 看的。

论文摘要给的结果：在编程任务的十组配对实验里，带这份记忆继续改进，最终得分比只继承 Harness 平均高 2.36 分（p=0.003）。论文也写明，除了这组配对实验，其余每个条件都只跑了一次完整流程。

**和以前有什么不同**

以前做提示词或流程的自动优化，默认「在评测集上分数高了就是好」。这两篇把机器学习里的老问题搬了过来：改进用的数据和验证用的数据要分开，改动要有预算，没用的部件要删，改进的经验要成体系地留下来。

**面试里怎么用**

被问「自动优化 Agent 有什么坑」或「怎么保证自我改进不跑偏」时：

> 最大的坑是过拟合。Agent 在用来改进的那批任务上分数上去了，换一批就不行，而且外壳越改越重。解法和训练模型时一样：改进集和验证集分开；分数提升要超过重复运行的噪声才算数；每轮可改的幅度有预算；定期把测不出收益的部件删掉。Google 的 RRSI 就是这么做的，在没见过的基准上也有提升，token 还少用了三成。另外改进的历史要按根因记下来，这样换模型或换任务之后不用从头再来。

**对应知识点**：[线上反馈、评估集与持续改进闭环](https://www.agent-journey.cn/knowledge?activeKey=agent-feedback-loop)、[Agent 评测原理：任务、轨迹与环境结果](https://www.agent-journey.cn/knowledge?activeKey=agent-eval-framework)、[上下文工程（Context Engineering）](https://www.agent-journey.cn/knowledge?activeKey=context-engineering)

## 3. Flex-RSI 和 RSI-Env：现在实际能做到什么程度

**发生了什么**

11 月初出了两个专门测 RSI 的环境，回答的是「各家模型自我改进的能力到底怎么样」。

**Flex-RSI：18 个模型同台比**

[Flex-RSI](https://arxiv.org/abs/2611.08946)（arXiv，2026-11-06）有 24 个视觉和机器人方向的任务，测了 18 个闭源和开源模型。每次运行里有两个角色：执行者负责改进任务的解法，改进者负责修改 Harness，修改范围包括执行者，也包括改进者自己。所有运行从同一个通用 Harness 出发，预算固定。

防作弊的设计是：执行者只在开发集上干活，候选解法在留出的验证集上得分更高才保留，否则回退；测试集只在全部结束后用一次；评分器、数据划分和预算统计 Agent 都改不了。

论文摘要的结论有两条：自我改进在 Agent 需要自己搭建解法的任务上帮助最大；只告诉 Agent 成功还是失败的反馈，会拖住开源模型。论文正文里，开源模型在对物理稳定性或精确正确性要求严格的任务上落后最多。

**RSI-Env：连模型权重一起改**

[RSI-Env](https://arxiv.org/abs/2611.01736)（复旦大学、香港科技大学、上海人工智能实验室等，arXiv 2026-11-03）更进一步，允许 Agent 既改 Harness 又训练自己的模型。起点是 Qwen3.8-27B 加一个极简的 Harness，一共 10 轮，每轮 3 小时。每一个被接受的版本负责跑下一轮改进。

几个结果：

- 开放目标下，GPQA Diamond 从 65.2 升到 73.2，这一组最终版本只改了 Harness，没有换模型。
- 知识类目标下，Agent 自己造了 48 条训练样本微调出新模型，SimpleQA 从 82.0 先到 85.0（只改 Harness），再到 88.0（加上新模型）。
- 但提升一项会掉另一项：开放目标那组的 SimpleQA 掉到了 77.2，知识类那组的 GPQA 掉到了 53.0。

论文自己的总结是进展仍然不均衡，难点在于提升某项能力的同时保住其他能力。

**和以前有什么不同**

以前 RSI 更多出现在 AI 安全的讨论里，是一个关于未来的概念。现在它有了可以跑分的基准，结论也具体了：在限定范围、限定预算、有独立验证的条件下，自我改进确实有效，但效果取决于模型本身的强弱，而且会出现顾此失彼。

**面试里怎么用**

被问「RSI 现在到什么程度了」或「你怎么看 Agent 自我进化」时：

> 现在能做到的是有边界的自我改进。在固定预算、评分和数据 Agent 都改不了的前提下，让 Agent 改自己的 Harness，多数情况下分数会上去。今年 11 月的 Flex-RSI 测了 18 个模型，结论是需要 Agent 自己搭方案的任务受益最大，开源模型明显落后。也有工作让 Agent 连模型一起训练，但会出现提升一项能力、另一项掉分的情况。所以落地时我会把它当成一个有闸门的离线优化流程，而不是让线上 Agent 随时自己改自己。

**对应知识点**：[Agent Benchmark 的设计与解读](https://www.agent-journey.cn/knowledge?activeKey=agent-benchmark)、[Agent 评测原理：任务、轨迹与环境结果](https://www.agent-journey.cn/knowledge?activeKey=agent-eval-framework)、[从零构建 Agent 运行时](https://www.agent-journey.cn/knowledge?activeKey=build-agent-framework)

## 一句话记住

RSI 现阶段等于「模型不动，Agent 在闸门的看管下改自己的外壳」。讲它的时候三件事要说全：改的是什么，靠什么验证，边界在哪。

想看只改 Harness 能省多少成本，可以接着读 [Harness 与长任务专题](https://www.agent-journey.cn/knowledge?activeKey=frontier-harness-long-running) 里的 SoL-Pi，它用的也是这种自动改进循环。

## 练一练

### 高频考点题 1：当前 RSI 改的是什么

2026 年下半年这批 RSI 论文里，多数工作让 Agent 自我改进时，实际被修改的主要是什么？

- A. 模型的权重参数
- B. 包在模型外面的 Harness，比如提示词、工具和控制流程
- C. 评测用的打分脚本
- D. 训练模型用的原始语料

**答案：B。** 这批工作大多把模型权重冻结，让 Agent 修改外面那层 Harness。改权重的只有少数工作在尝试；打分脚本恰恰是必须隔离、不让 Agent 接触的部分；原始训练语料不在这类改进的范围里。

### 高频考点题 2：验证闸门防的是什么

自我改进流程里，候选版本要在留出的验证集上确认没有退步才合入，并且评分脚本放在 Agent 接触不到的地方。这样设计主要是为了防止什么？

- A. Agent 运行速度太慢
- B. 模型权重在改进过程中丢失
- C. 改进只对用来改进的那批任务有效，或者 Agent 直接去改评分
- D. 多个 Agent 之间抢占同一个端口

**答案：C。** 留出验证集是为了发现过拟合，也就是分数只在用来改进的那批任务上变好；把评分脚本隔离是为了避免 Agent 朝着改评分的方向优化。运行速度、权重保存和资源抢占都不是这道闸门要解决的问题。

### 高频考点题 3：RRSI 的正则化

RRSI 给 Harness 的自我改进加了正则化。下面哪一项符合它的做法？

- A. 分数提升要超过重复运行量出的噪声带才算数，并且删掉测不出收益的部件
- B. 每一轮都把整个 Harness 推倒重写
- C. 只要在改进用的任务上分数变高就立刻合入
- D. 改动幅度随轮次增加而不断放大

**答案：A。** RRSI 用重复运行未改动的 Harness 来估计噪声，提升超过噪声才接受，并用修剪器删除没有正收益的部件。它的改动预算是随轮次收紧的，也不会整体推倒重写；只看改进集分数就合入正是它要避免的过拟合做法。
