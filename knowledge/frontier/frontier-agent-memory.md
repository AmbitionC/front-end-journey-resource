本期专题是 Agent 记忆。面经里记忆是提及最多的几个方向之一，过去的标准答案是「短期放上下文、长期放向量库」。这三条说明这个答案已经不够用了。

> **本期 30 秒版**
> 1. 记忆可以分层来做，不必只是一个向量库：Anthropic 把记忆拆成原始记录、笔记、整理后的知识页和每次都加载的一小段，并用离线整理（dreaming）在几层之间做提炼。
> 2. 记忆对了也可能把答案带偏：MemAdapter 论文测到，加入准确且相关的记忆后，一组题的准确率从 96.0% 掉到 77.3%。
> 3. 记忆系统可以按「会不会自己改写入策略」分三档：一篇多模态记忆综述梳理了 297 个记忆架构，给出静态、动态、自演化的分法。

## 1. Anthropic 讲 Agent 记忆的组成：四层结构加离线整理

**发生了什么**

Anthropic 2026 年 11 月 6 日发文 [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)（作者 Lance Martin），把记忆讲成一个自下而上的四层结构：

| 层 | 内容 | 怎么用 |
| --- | --- | --- |
| 原始记录 | 完整的会话和操作日志 | 可检索，不直接进上下文 |
| 记忆笔记 | Agent 自己写下的笔记 | 需要时去读 |
| 记忆表示 | 整理后的知识页，比如 wiki | 按主题查 |
| 注入的上下文 | 每次会话都加载的一小段 | 始终可见，必须很小 |

层与层之间靠「dreaming」连接：Agent 不在任务中的时候做离线整理，对照原始记录修正笔记、把笔记合并成知识页、把常用的内容提升到上层。

**几组值得记的数字**

- 在 CL-Bench 的一个数据库任务上，同一个模型不带记忆和带记忆的得分：Claude Opus 5.5 从 0.655 到 0.838，Claude Opus 4.7 从 0.383 到 0.700。Claude Sonnet 4.6 只从 0.330 到 0.364，把指令改成「先读记忆、再验证自己的猜测」之后到了 0.641。也就是说，较弱的模型需要更明确的记忆使用指令。
- 记忆该记什么，不要管得太死。加一条「只记录失败」的规则后，记忆带来的增益反而下降：Opus 5 降 0.234，Opus 4.7 降 0.150。
- 整理是有用的。在一个约 35 万个文件的资料库问答任务（25 道题）上，离线整理从 2 次做到 128 次，得分从 13% 升到 48%。只用检索是 53%，知识页加检索从 54% 升到 61%。
- 整理也会丢信息。一个合同任务里，把多份合同汇总进一张共享表的做法只保住了 57 条事实中的 41 条（72%），而每份合同一页、逐字引用的做法保住了全部 57 条。
- Claude Code 每次只加载 MEMORY.md 的前 200 行或 25 KB。

文章自己列的局限：离线整理要花算力，整理出的知识页可能比原始材料还大，有些任务上记忆没有带来提升。

**和以前有什么不同**

以前讲长期记忆，重点在「存进向量库、用的时候召回」。这篇的重点换成了三件事：原始记录要留着并且可检索，它是其他几层的底；每次都加载的那一层要尽量小；记忆的质量靠事后整理，不靠写入时一次写对。给模型的指导也从「规定怎么记」变成「说明记忆是用来干什么的」。

**面试里怎么用**

被问「Agent 的长期记忆怎么设计」时：

> 我会分层。最底下是完整的原始记录，只做检索不进上下文；往上是 Agent 自己写的笔记，再往上是按主题整理的知识页，最上面是每次会话都加载的一小段，这一层要严格控制大小。层与层之间靠离线整理来提炼，而不是指望写入时一次写对。Anthropic 公布过数据，离线整理次数增加后问答得分明显提升，但把多份材料合并成摘要会丢事实，所以需要精确信息的内容要一个实体一页、逐字引用，并且保留原始记录可回查。

## 2. MemAdapter：记忆是对的，答案也可能被带偏

**发生了什么**

吉林大学和厦门大学的论文 [MemAdapter](https://arxiv.org/abs/2610.05162)（arXiv，2026-10-04）研究了一个容易被忽略的问题：模型会过度迎合记忆里的内容，论文叫它「记忆引发的迎合」。

关键观察是：即使加入的记忆是准确且相关的，也会出问题。论文的一组实验里，加入记忆后准确率从 96.0% 掉到 77.3%，原本答对的题里有 19.4% 被改错，而且全部是朝记忆内容的方向改的。

**做法**

MemAdapter 是一个放在检索之后的处理步骤，不改记忆库本身，分三步：

- 反事实归纳（Counterfactual Induction）
- 结合上下文的反思（Context-Aware Reflection）
- 基于证据的推理（Evidence-Based Reasoning）

思路是让模型先做一次对照，再判断记忆和当前问题的关系，最后依据证据作答，而不是直接顺着记忆说。

在论文的 MemSyco-Bench 上（模型为 DeepSeek-V4-Flash），普通 RAG 的平均准确率从 70.25 升到 89.94，A-MEM 从 71.71 升到 90.45。

**和以前有什么不同**

过去谈记忆的风险，主要是「记错了」和「被投毒」，解法是提高写入质量和做校验。这篇指出第三种风险：记忆没错，但模型把它看得太重，把「用户以前这样说过」当成了「现在应该这样答」。所以召回之后、使用之前，还需要一步判断。

**面试里怎么用**

被问「记忆召回之后直接拼进提示词有什么问题」或「个性化记忆有什么副作用」时：

> 除了召回不准，还有一个问题是模型会迎合记忆。有论文测过，即使加进去的记忆是准确且相关的，原本能答对的题也有近两成被改错，而且都是朝记忆的方向偏。所以我会在召回之后加一步判断：这条记忆和当前问题是否真的相关，不用它时答案是什么，两者不一致时以当前证据为准。评测记忆系统时，除了看召回率，还要专门测加了记忆后原本答对的题有没有变错。

**对应知识点**：[短期记忆、长期记忆与检索](https://www.agent-journey.cn/knowledge?activeKey=agent-memory)、[记忆污染与持久化攻击](https://www.agent-journey.cn/knowledge?activeKey=agent-memory-poisoning)、[遗忘策略、冲突处理与记忆更新](https://www.agent-journey.cn/knowledge?activeKey=agent-memory-forgetting)

## 3. 多模态记忆综述：按「写入策略会不会变」给记忆系统分三档

**发生了什么**

罗格斯大学、圣母大学、密歇根大学、复旦大学等机构合写的综述 [Seeing, Maintaining, and Learning: The Evolution of Multimodal Agent Memory](https://arxiv.org/abs/2610.19366)（arXiv，2026-10-14）梳理了 297 个记忆架构和 82 条基准记录。

它用两条轴来整理：一条是记忆怎么形成和表示，另一条是记忆怎么管理。在管理这条轴上分了三档：

| 档 | 名称 | 特点 |
| --- | --- | --- |
| T1 | 静态记忆 | 记忆内容固定，只是重复使用 |
| T2 | 动态记忆 | 记忆会更新，但更新规则是固定的 |
| T3 | 自演化记忆 | 更新规则本身也会跟着经验调整 |

**和以前有什么不同**

常见的分法是按内容分（情景、语义、程序）或按时间分（短期、长期）。这个分法换了角度，看的是「谁来决定记什么、怎么改」。对着第 1 条看很清楚：固定规则的写入是 T2，让 Agent 自己整理、自己决定提升什么的做法已经在往 T3 走。

**面试里怎么用**

被问「你了解哪些记忆方案、怎么比较」时，可以用这个分法组织回答：

> 我会先看记忆的更新方式。最简单的是静态的，比如一份固定的知识库；多数产品是动态的，按固定规则写入、合并和淘汰；更进一步是让 Agent 自己调整写入和整理的策略。越往后越灵活，但也越难评测和回滚，所以我会先用固定规则跑通，保留原始记录，再在有评测集的前提下放开让 Agent 自己整理。

**对应知识点**：[Agent 记忆系统架构设计](https://www.agent-journey.cn/knowledge?activeKey=agent-memory-architecture)、[遗忘策略、冲突处理与记忆更新](https://www.agent-journey.cn/knowledge?activeKey=agent-memory-forgetting)
