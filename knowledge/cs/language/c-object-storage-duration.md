判断 C 对象“放在哪里”，先分清语言规定的存储期与实现采用的内存布局。存储期决定对象何时存在；栈、寄存器、数据段等描述具体实现的承载方式，两者不能直接画等号。学会这一区分，才能解释局部变量、`static`、`malloc` 和悬空指针，而不是把所有“临时变量”都回答成栈变量。

## 先区分对象、名字和指针值

对象是一段用于保存值的存储；变量名是在某个作用域中访问对象的名字。`int *p` 声明的对象是指针 `p` 本身，`malloc` 成功后另外获得的对象则由它指向。两个对象可以有不同的生命周期。

作用域回答名字在哪里可见，存储期回答对象何时存在。因此，函数内的 `static int count` 名字只在相应块中可见，对象却可以跨调用保留。本篇以 [C11 委员会草案 N1570 §6.2.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) 为固定语义范围，不把 C++ 的对象初始化规则混入 C。

## 四种存储期怎样判断

| 存储期 | 示例与主要生命周期 | 不能由此推出什么 |
| --- | --- | --- |
| 自动存储期 | 普通非变长数组的块内局部对象，如 `int x = 1`，从进入关联块到离开该块 | 每个对象都必须有一个真实栈槽 |
| 静态存储期 | 未声明 `_Thread_local` 的文件作用域对象，或未声明 `_Thread_local` 的块内 `static` 对象，贯穿程序执行 | 名字到处可见，或并发修改自动安全 |
| 线程存储期 | 如文件作用域的 `_Thread_local int state`，每个线程有自己的对象，持续到该线程结束 | 多个线程共享同一份该对象 |
| 分配存储期 | 成功分配获得的对象，持续到对应释放 | 保存地址的局部指针退出时，对象自动释放 |

这是语言层的分类。变长数组的自动对象有更具体的起始规则：从其声明开始，直到执行离开相应作用域。看到题目中的声明后再判断，不能将普通局部对象的表述机械覆盖所有情况。

## 一个局部指针，为什么能把对象交给调用方

以下是单线程教学程序，按 C11 编译。它同时演示静态计数对象和动态分配对象；失败分支不解引用空指针。

```c
#include <stdlib.h>

static int next_count(void) {
    static int count = 0;
    return ++count;
}

static int *make_number(void) {
    int *p = malloc(sizeof *p);
    if (p != NULL) {
        *p = 42;
    }
    return p;
}

int main(void) {
    int local = 7;
    int *value = make_number();
    if (value == NULL) {
        return 1;
    }

    int result = *value;
    free(value);
    value = NULL;

    if (local != 7 || result != 42) {
        return 2;
    }
    if (next_count() != 1 || next_count() != 2) {
        return 3;
    }
    return 0;
}
```

`make_number` 返回的是指针值。返回后，局部对象 `p` 已结束，但成功分配的对象仍然存在；调用方的 `value` 保存了这个地址。调用方读取并释放它，随后将自己的指针置空。`count` 则在两次调用之间保留，所以依次得到 1 和 2。

这里没有返回局部整数的地址。如果把函数内普通 `int x` 的地址交出去，函数返回后 `x` 已不在生命周期内，调用方不能再通过该地址访问它。把地址存到全局变量，也不会延长 `x` 的生命周期。

[§7.22.3 的内存管理规则](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)规定了分配与释放的边界：`malloc` 可能失败；成功后应先初始化再读取；`free` 只接受适用的分配结果或空指针，重复释放等行为不合法。不要在释放后继续使用原地址，给一个指针置空也不会修复其他已经复制出的别名。

## 为什么不能保证“自动对象就在栈上”

编译器必须保持 C 抽象机器要求的可观察行为，但可以改变内部实现。一个只参与计算、地址未逃逸的局部值，可能用寄存器承载，也可能被常量传播或消除。调试器中找不到某个变量，不足以证明源程序没有这个对象或该路径没有执行；[GCC 优化说明](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html)讨论了寄存器分配与多种消除、传播优化。

栈、堆和静态数据区仍然是理解常见 ABI 与进程布局的有用模型，但观察具体位置时必须说明编译器、目标、选项和实际代码。编译选项的对比实验只能证明那组条件下的实现，不能反推为所有 C 程序的布局要求。

## “临时变量”题应该怎样回答

先请求具体声明或说明自己的解释。如果它指普通非 `static` 的块内局部对象，回答自动存储期，再说明常见实现和优化边界；如果声明带 `static` 或 `_Thread_local`，按对应存储期判断；如果它只是保存 `malloc` 地址的指针，分别分析指针和所指对象。

C11 还对部分结构体或联合体非左值表达式规定了临时生命周期。这是特定表达式规则，不等于口语中所有“临时变量”；没有代码时，不替题目假定属于这一类。

可以用三问自检：现在说的是哪个对象，它的生命周期从何时到何时，当前访问是否仍在这个范围内。答清这三问，再讨论栈、寄存器或分配器，结论才有确定的适用边界。
