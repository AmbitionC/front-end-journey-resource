现代操作系统把普通程序与内核放在不同特权级运行。用户态代码可以计算和访问自己的虚拟地址空间，但不能直接修改页表、控制设备或读取任意物理内存；这些能力由内核通过受控入口提供。这个边界既限制错误影响范围，也是权限、资源记账和进程隔离的基础。

## 为什么需要特权边界

如果任何程序都能执行特权指令，一个越界指针就可能改写其他进程或内核内存，恶意程序也能关闭中断、修改页表或直接控制磁盘。操作系统通过 CPU 特权级和页表权限建立隔离：

- 用户态只能执行非特权指令并访问获准映射的页面；
- 内核态可以管理页表、调度、设备、中断和全局资源；
- 应用通过系统调用请求能力，内核再次验证参数、身份和权限；
- 进程崩溃通常被限制在自己的地址空间，内核故障则可能影响整机。

“用户态”和“内核态”描述的是 CPU 当前执行权限，不等同于某个具体进程。内核可以代表当前线程处理系统调用，也可以处理与该线程无关的设备中断。

## 哪些工作通常在用户态或内核态

| 用户态 | 内核态 |
| --- | --- |
| 业务逻辑、解析、计算、UI | 进程与线程调度 |
| 运行时、标准库的大部分代码 | 虚拟内存、页表与缺页处理 |
| 已映射内存中的普通读写 | 文件系统、网络协议栈和设备驱动 |
| 通过库封装发起资源请求 | 权限检查、资源记账和中断处理 |

库函数不必然进入内核。例如 `strlen` 只读取用户内存；`printf` 可能先写用户态缓冲区，真正刷新时才调用 `write`。判断是否切换应看是否触发受控入口，而不是看函数名是否属于标准库。

## 进入内核的三类入口

[Linux 内核 Entry/Exit 文档](https://docs.kernel.org/core-api/entry.html)把底层入口区分为系统调用、中断和异常等路径。面试中可按触发者与同步关系回答。

### 系统调用：应用主动请求

应用要读文件、发网络包、创建进程或改变映射时，通过体系结构规定的 syscall 指令进入内核。CPU 切换特权级和入口，内核根据系统调用号找到处理函数，复制或校验用户参数，完成操作后返回。

[Linux 系统调用手册](https://man7.org/linux/man-pages/man2/syscalls.2.html)列出了系统调用接口。语言运行时和 libc 往往提供包装器，但包装函数与真正的内核系统调用是两个层次。

### 异常或故障：当前指令同步触发

缺页、除零、非法指令和权限错误由当前正在执行的指令触发，因此是同步的。以缺页为例，CPU 访问一个尚未映射但合法的虚拟页时进入内核；内核判断地址和权限，分配或加载页面、更新页表，再重新执行原指令。若访问非法，则向进程发送信号而不是“补一页”。

### 硬件中断：外部事件异步到达

时钟、网卡和存储设备完成事件可以在指令之间打断当前执行流。内核保存必要现场，处理中断或安排后续延迟工作。时钟中断可能让调度器获得运行机会，但“发生中断”不代表一定切换到另一个线程。

## 一次入口和返回发生什么

具体寄存器与栈布局依赖 CPU 架构，但一般包含：

1. 保存返回地址、状态寄存器和必要现场；
2. 切换到内核规定的入口与内核栈；
3. 建立可供 C/汇编处理器使用的上下文；
4. 进行参数、权限与状态校验；
5. 执行内核服务，期间可能阻塞或被调度；
6. 处理待决信号、抢占等退出工作；
7. 恢复现场与用户权限，从中断/异常或 syscall 返回。

用户指针不能直接信任。地址可能无效、跨页、在校验后变化，或故意指向未授权区域；内核使用专门的 `copy_from_user` / `copy_to_user` 等机制安全访问，并处理可能发生的 fault。

## 特权级切换不等于上下文切换

这两个概念经常被混淆：

- **用户态 → 内核态**：CPU 改变权限并进入内核，处理完后可能返回同一个线程；
- **线程上下文切换**：调度器保存当前线程的寄存器、栈和调度状态，加载另一个线程；
- **进程切换**：除线程状态外，通常还涉及地址空间或相关映射上下文变化。

一个快速的 `getpid` 系统调用可以进入内核后返回原线程，没有发生调度切换。反过来，系统调用因等待磁盘而阻塞时，内核可能选择另一个线程，这时两种切换都发生了。时钟中断进入内核后也可能发现无需抢占，直接返回原线程。

## 缺页怎样串起两种状态

用户态访问虚拟地址时，MMU 查 TLB 和页表。若页面不存在或权限不符，CPU 触发 page fault 进入内核：

1. 内核判断地址是否属于合法 VMA；
2. 合法匿名页可分配零页，文件映射可从文件读取，写时复制可分配新物理页；
3. 更新页表与必要的 TLB 状态；
4. 若需要 I/O，当前线程可能阻塞并发生上下文切换；
5. 页面就绪后重新执行出错指令；非法访问则向进程报告错误。

所以 Page Fault 并不必然意味着磁盘 I/O，也不等于进程一定切换。更多内存机制见[内存、虚拟内存与分页](./os-virtual-memory.md)。

## 性能开销怎样分析

系统调用的开销包含入口/退出、参数检查、缓存与真正服务成本；上下文切换还可能影响 CPU Cache、TLB 和分支预测。不能用一个固定纳秒数概括所有机器和调用。

优化应从测量开始：使用 tracing 或 profiler 区分用户 CPU、system CPU、阻塞时间、调度等待与设备延迟。常见方向包括批量 I/O、复用连接、减少无意义小调用、使用异步接口或共享内存，但不能为了“少切换”绕过权限和正确性边界。

## 与 Agent Sandbox 的关系

Agent 生成的代码通常在用户态受限进程中运行。容器 namespace、cgroup 和文件权限负责隔离资源；`seccomp` 可以限制允许进入内核的系统调用集合；更强隔离还会使用虚拟机或用户态内核。宿主 supervisor 负责生命周期、配额、网络策略和审计。

沙箱不是因为代码“在用户态”就天然安全：系统调用仍可进入共享宿主内核，内核漏洞、错误挂载或过宽权限都可能突破边界。生产设计要组合最小权限、只读镜像、网络白名单、资源限制、内核加固与销毁后检查。

## 常见误区

- 普通函数调用不会因为“调用了库”就自动进入内核；
- 用户态与内核态切换不一定伴随进程或线程切换；
- Page Fault 是异常入口，不是传统意义上的外设中断；
- 虚拟内存不等于“用磁盘模拟内存”，交换只是其中一种策略；
- `mmap` 后访问页面仍可能触发缺页，映射本身不保证数据已驻留；
- 减少系统调用不是越少越好，正确的权限检查和资源边界不能省略。

## 面试回答模板

可以用四步回答：先说**目的**是保护与资源管理；再说**三类入口**是系统调用、异常和硬件中断；随后描述**CPU 保存现场—进入内核—校验处理—返回**；最后明确**特权级切换不等于上下文切换**，并用缺页或网络 I/O 举例。这样比只背“用户态权限低、内核态权限高”更完整。

## 小结

用户态与内核态是硬件特权和操作系统策略共同建立的保护边界。系统调用让应用主动请求服务，异常处理当前指令的同步问题，硬件中断响应外部事件；进入内核后是否调度到其他线程，要由阻塞与调度条件决定。理解这一区分，才能正确分析系统调用、缺页、网络 I/O、性能和 Agent 沙箱安全。
