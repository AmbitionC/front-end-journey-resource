训练一个现代大模型，不是把海量文本一次性“喂给 Transformer”就结束。它是一条从数据治理、预训练、评估到后训练和上线监控的循环流水线；每个阶段优化的目标、使用的数据和能解决的问题都不同。

## 先看全生命周期

![从数据预训练到后训练安全评估和部署监控的大模型生命周期](https://font-end-journey-resources.oss-cn-hangzhou.aliyuncs.com/images/llm-training-overview-lifecycle-v1.webp)
*图：预训练获得通用预测能力，后训练塑造交互行为；评估与线上反馈会反向推动数据和训练策略迭代。*

一个典型流程可以拆成九步：数据收集、清洗去重、tokenize、预训练、基础能力评估、监督微调、偏好优化、安全评估、部署与监控。真实团队会交叉迭代这些步骤，而不是严格只走一遍。

## 阶段一：定义目标与数据契约

训练前要先决定模型服务什么任务、覆盖哪些语言与代码、上下文多长、许可和隐私边界是什么。否则“数据越多越好”会把重复、低质、敏感信息和评测题答案一起扩大。

数据流水线通常包含：

- 来源登记、许可与使用限制；
- 语言和内容类型识别；
- 质量、恶意内容与个人信息过滤；
- 精确去重和近似去重；
- 数据混合比例与采样权重；
- 训练集、验证集及基准污染检查。

[Llama 3 技术报告](https://arxiv.org/abs/2407.21783) 把数据过滤、去重、混合和质量分类作为预训练的重要组成部分，也说明模型能力不只由参数数量决定。

## 数据合成：把生成样本变成可验证的数据

合成数据是为目标任务构造新的输入、答案或交互轨迹，不等于把已有文本清洗一遍。[Self-Instruct](https://arxiv.org/abs/2212.10560) 展示了“生成指令、输入与输出，再过滤无效或相似样本”的流程；它是方法实例，不能据此假定所有 Agent 任务都适合模型自生成、自打分。

先说明要补哪类能力，再选生成方式：规则组合适合边界明确的参数与状态；模型生成适合扩展表达和候选任务；可执行环境采样适合得到工具动作及状态变化。不要只增加容易成功的样本。面向有状态 Agent，可把每条样本组织成以下工程契约：

| 记录 | 要回答的问题 |
| --- | --- |
| 任务与来源 | 目标、允许动作、能力标签、初始状态是什么；模板或原始样本来自哪里 |
| 生成过程 | 使用哪个生成器、模型、提示版本、参数与随机种子；同源变体属于哪一组 |
| 验证证据 | 哪个版本的规则、测试或人工标准判定；实际终态、错误与筛除原因是什么 |
| 数据分集 | 任务族、模板或用户分组进入哪个集合；是否与保留评测重叠 |

生成器产出的“成功轨迹”仍是候选。代码可运行不代表满足全部需求，Agent 最终说“完成”也不代表环境终态正确。[Llama 3 技术报告 §4.3.1](https://arxiv.org/html/2407.21783v3#S4.SS3.SSS1) 使用语法检查与执行反馈改进合成代码；[WebArena](https://arxiv.org/abs/2307.13854) 则以功能正确性检验任务完成。可执行条件优先由受控测试或环境状态验证；开放质量再用经校准的 Judge 或人工复核，判定器只能覆盖它明确检查的条件。

例如“为符合条件的订单创建一次退款”可以合成正常、无权限、已退款和提交后响应丢失等初始状态。验证应读取退款记录、金额与副作用，检查既完成目标又没有重复写入；用例可接受多种合法执行路径，不要求机械模仿唯一轨迹。任务环境的状态转移、重置与故障注入见[用户模拟器与环境模拟测试](../production/agent-simulation.md)。

污染检查要同时考虑原始材料和生成后的样本。先按同源模板或任务族划分，再在各集合内生成变体，能减少改写样本被随机分到训练与测试两侧的泄漏；还应做精确与近重复比对，保留独立验收集。隐藏验收条件不能作为额外提示泄露给生成器或被测 Agent。最后用固定、未参与本轮生成和调优的任务集比较效果，不能把合成集上的通过率直接当业务收益。

## 阶段二：Tokenizer 与样本构造

Tokenizer 把原始文本变成 token ID。训练系统再把文档拼接或切分成固定长度样本，并构造 attention mask、位置编码和目标标签。

这里的选择会影响：多语言 token 效率、代码与空白保留、文档边界是否泄漏、长上下文利用率，以及训练中有多少 token 只是 padding。Tokenizer 一旦改变，embedding 和输出层的词表含义也随之改变，不能把旧 checkpoint 当成完全兼容。

## 阶段三：预训练

解码器式语言模型通常做 next-token prediction：给定前缀，最小化正确后续 token 的负对数似然。通过在大量样本上反复优化，模型学习语言结构、事实关联、代码模式和部分可迁移的任务能力。

[GPT-3](https://arxiv.org/abs/2005.14165) 展示了自回归预训练模型可通过提示和少量示例完成多种任务，而无需为每个任务更新参数。但预训练目标只要求预测文本，不天然要求遵循用户意图、拒绝危险请求或提供可验证来源。

大规模训练还需要分布式工程：数据并行切分样本，张量并行切分矩阵，流水线并行切分层，checkpoint 定期保存优化器与模型状态。吞吐、通信、数值稳定性和故障恢复都会影响最终可用训练量。

## 阶段四：预训练评估

训练 loss 下降只说明更会预测训练分布。团队还要检查：

- 保留验证集上的 loss 与困惑度；
- 语言、代码、数学、知识和长上下文等能力基准；
- 数据污染和记忆复现；
- 不同群体与语言上的性能差异；
- 毒性、隐私、网络安全和其他风险探针。

评估结果必须带版本、提示模板、解码参数和数据集版本。单个聚合分数无法替代真实业务任务的错误分析。

## 训练、验证与泛化：欠拟合和过拟合怎么判断

**欠拟合**是模型还没有充分学会任务中可学的规律，**过拟合**是过度适应训练样本，导致未见数据上的表现变差。判断依赖未参与当前参数学习的数据，以及与任务有关的指标，不能只看训练 loss 的一个数值。[Google：过拟合与泛化](https://developers.google.com/machine-learning/crash-course/overfitting/overfitting)。

训练集用于更新参数，验证集辅助选择超参数和 checkpoint，测试集用于在确定方案后检查泛化。按用户、文档或时间分组划分可减少近重复泄漏；选择方式取决于实际部署分布。反复根据测试结果挑模型，就把测试集用于调优了，应另保留独立验收数据。[Google：划分训练、验证与测试数据](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets)。

| 观察到的现象 | 可以提出的诊断 | 还应核实什么 |
| --- | --- | --- |
| 训练和验证指标都很差 | 表达能力、有效训练量或优化可能不足 | 标签噪声、目标定义、数据分布是否合理 |
| 训练持续改善，验证在同条件下退化 | 可能对训练数据过拟合 | 数据泄漏、样本量与方差、评测条件是否变化 |
| 验证 loss 改善，业务成功率却下降 | 优化目标与业务要求可能不一致 | 错误切片、交互行为、工具与环境的变化 |

这些是诊断线索，不能单凭曲线给模型定性。欠拟合可能通过改进特征、模型容量或优化解决，但增加训练轮次不能修复错误标签；过拟合可考虑更可靠和多样的数据、适当正则化、早停或减少容量，但各方法要在相同验证条件下比较。更大的模型、更低训练 loss 或更多 epoch 都不是普遍答案。

大模型还需区分预训练、SFT 和实际 Agent 执行：窄数据上的 SFT 可能改善示范任务却损害其他能力，应检查覆盖范围和能力回归，而不能据此直接认定原因是过拟合；Agent 出错也可能来自检索、工具契约或运行环境，并非模型欠拟合。先定位错误落在哪一层，再决定是否需要训练。[Llama 3 技术报告](https://arxiv.org/abs/2407.21783)。

## Mid-training 与 Post-training：名称边界须说明

Mid-training 常用于描述预训练后、最终任务对齐前的继续训练，例如调整领域、长上下文或能力分布；不同团队的划分并不一致。Post-training 通常强调指令、偏好、安全与任务策略，可包含 SFT、偏好优化和强化学习。回答时说明输入数据、目标函数、是否更新参数和要改变的能力，比只背阶段名称更可靠；沿用某个报告的名称时应同时给出该报告的定义。

## 阶段五：监督微调（SFT）

预训练模型会续写文本，却不一定按“用户—助手”协议回答。SFT 使用高质量的指令—回答示范，继续做有监督的 token 预测，让模型学习任务格式、语气、工具调用结构和拒答范式。

SFT 的关键不是简单堆数量，而是覆盖行为边界并保持示范一致。矛盾示范会让模型学到不稳定策略；过窄数据则可能牺牲基础能力。

## 阶段六：偏好优化

同一提示通常存在多个“语法正确但质量不同”的回答。偏好数据以 chosen/rejected、排序或评分表达帮助性、真实性、风格和安全要求。

[InstructGPT](https://arxiv.org/abs/2203.02155) 的经典流程先用示范做 SFT，再训练奖励模型，最后用 RLHF 优化策略。现代流水线也可能使用 DPO 等直接偏好方法。它们塑造的是数据和评价标准定义的行为分布，不会自动产生客观、普适的价值函数。

## 阶段七：安全评估与发布门禁

上线前应使用独立于训练数据的测试集，覆盖越权、提示注入、危险建议、隐私泄露、偏见、过度拒答和工具误调用。红队发现的样本可以进入下一轮数据，但不能用“训练过这些题”代替保留集评估。

发布通常还需要比较新旧模型：核心任务是否提升、已知回归是否复现、延迟与成本是否可接受、量化或服务优化是否改变质量。

## 阶段八：部署与持续监控

生产中的输入分布会漂移，模型和工具也会升级。系统应记录模型版本、提示版本、工具轨迹、延迟、成本、失败类型和用户反馈，并对敏感数据做最小化与脱敏。

监控发现的问题可能回到不同环节：知识过时可优先修检索；格式失败可修 schema/后训练；基础能力缺口才可能需要继续预训练或新一代基座。不是每个线上问题都值得重新训练模型。

## 常见误区

- **训练 loss 更低就一定更好用**：交互行为、事实性和安全性需要单独评估。
- **后训练能注入无限新知识**：少量微调更适合塑造行为；频繁变化知识应外接检索。
- **benchmark 高就能直接上线**：业务分布、权限和副作用与公开题库不同。
- **安全只在最后过滤**：数据、目标、后训练、工具设计和运行时策略都参与安全。
- **训练完成就是项目完成**：真正生命周期还包括服务优化、监控、回滚和持续评估。

## 小结

大模型训练是一套闭环系统：预训练学习通用分布，SFT 学习示范行为，偏好优化调整选择倾向，安全评估与线上监控约束真实使用。把阶段和目标分开，才能针对问题选择正确的改进手段。

## 统一构造与真实用户回流怎样比较

统一管线构造可以面向任务或数据，不必限定成离线训练管线：它便于控制输入、覆盖、版本与验证条件。用户回流更贴近真实使用，但采样不一定代表全部用户；沉默、放弃、延迟反馈和只上报成功都可能扭曲样本。先说明实际任务来源，再比较覆盖、标注或验证、隐私、时效和复现成本。

回流日志不能直接等同训练标签。先按权限脱敏与隔离，再把失败归因形成可验证案例，去重、检查反馈质量和泄漏，固定版本后进入评测；确需训练时再经数据契约进入训练集。可参考[Agent反馈闭环](../production/agent-feedback-loop.md)，但原面经未披露的管线实现不能补为作者经历。
