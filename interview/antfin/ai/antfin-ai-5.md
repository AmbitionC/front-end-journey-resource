### 蚂蚁智能体与大模型应用一面：幻觉、Skill 与 RAG（2026 年 5 月）

这场一面从大模型幻觉与微调切入，继续追问 Skill、Coding Harness、代码检索与 RAG，最后覆盖网络、数据库和 Spring 基础。

#### （1）大模型幻觉应该怎样治理？

先区分知识缺失、检索错误、工具结果解析失败和模型未遵循证据。对事实问题用可信检索、引用和无答案阈值约束；工具输出做 Schema 校验；高风险结论增加规则或人工确认。评测时按场景建立事实一致性集，不能只在 Prompt 中写“不要编造”。

延伸阅读：[大模型的能力边界、幻觉与不确定性](../../../knowledge/llm/basics/llm-capability-boundaries.md)。

#### （2）常见微调方法怎样选择？

监督微调适合学习任务格式和领域行为，LoRA 等参数高效方法用于降低训练与部署成本；偏好优化适合调整回答偏好和安全边界。若问题来自知识更新或证据缺失，优先考虑 RAG；若来自流程和工具约束，优先改运行时与校验，不应把所有问题都交给微调。

延伸阅读：[模型对齐：SFT、偏好数据与安全](../../../knowledge/llm/basics/llm-alignment.md)。

#### （3）Agent Skill 应该怎样实现和编写？

Skill 是可按需加载的任务说明与资源包，应明确触发条件、输入输出、步骤、失败边界和验证方式。正文保持渐进披露，脚本和模板放在独立资源中；版本升级要有兼容策略和回归样例，不能把 Skill 写成无限权限的自然语言命令。

延伸阅读：[Agent Skill：渐进式披露、热插拔与版本治理](../../../knowledge/llm/agent/agent-skill-design.md)。

#### （4）怎样比较 Spring AI 的 Skill 调用与 Claude Code 一类 Harness？

比较重点不是名称，而是职责边界：谁负责上下文装配、工具发现、循环控制、权限、状态恢复和观测。应用框架通常提供模型与工具集成；Coding Harness 还要管理代码库检索、文件修改、命令执行、测试和人工审批。回答时应说明项目实际需要哪些能力。

#### （5）学习 Claude Code 一类 Coding Agent，应该关注什么？

关注端到端运行机制：如何理解仓库、选择工具、控制改动范围、执行测试、压缩上下文、恢复任务和处理权限。评估时使用真实代码任务和可复现测试，观察最终正确率、无效操作、延迟与成本，而不是只看一次演示。

延伸阅读：[Coding Agent 的架构与执行循环](../../../knowledge/llm/agent/agent-coding.md)。

#### （6）代码检索为什么可以用 grep，而不一定先上 RAG？

grep 对符号名、错误码和精确文本低成本、可解释且结果新鲜；代码 RAG 更擅长语义查找、跨文件关系和自然语言问题，但需要切分、索引更新与召回评估。工程上通常先做确定性搜索，再在结果不足时使用语义检索，两者互补。

#### （7）RAG 混合召回怎样实现？

关键词检索负责专有名词与精确匹配，向量检索负责语义近似；两路先做权限和元数据过滤，再用 RRF 或归一化分数融合，最后 rerank。通过 Golden Set 分析每一路的命中贡献、漏召回和无答案场景。

延伸阅读：[Hybrid Search 混合检索](../../../knowledge/llm/rag/rag-hybrid-search.md)。

#### （8）输入 URL 后会经历哪些关键步骤？

浏览器解析 URL，查询 DNS，建立 TCP 与 TLS 连接，发送 HTTP 请求；服务端经网关与应用处理后返回响应，浏览器再解析资源、构建页面并执行脚本。回答时要区分连接复用、缓存命中和 HTTP/2、HTTP/3 等不同路径。

#### （9）TCP 为什么三次握手、通常四次挥手？

三次握手让双方确认彼此的发送、接收能力并同步初始序列号。TCP 两个方向独立关闭，因此主动关闭一方的 FIN 与对方的 FIN 通常分开发送，形成四次挥手；若 ACK 与 FIN 合并，也可能少于四个报文。

延伸阅读：[TCP 建连、断开与连接状态](../../../knowledge/network/tcpIp/tcp-handshake.md)。

#### （10）MySQL 为什么常用 B+ 树索引？

B+ 树分支因子高、树高低，节点适合页式存储；数据集中在叶子且叶子有序相连，兼顾点查、范围扫描和排序。回答还应说明联合索引最左前缀、覆盖索引、回表以及低选择性字段不一定适合建索引。

延伸阅读：[数据库索引原理与查询优化](../../../knowledge/backend/database/mysql-index.md)。

#### （11）Spring IoC 与 AOP 分别解决什么问题？

IoC 把对象创建、依赖装配和生命周期交给容器，降低组件耦合并便于测试。AOP 将事务、日志、权限等横切逻辑通过代理织入业务调用；需说明代理边界、自调用失效和异常回滚等常见限制。
