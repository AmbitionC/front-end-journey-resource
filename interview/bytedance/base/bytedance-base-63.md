# 字节抖音电商 Agent 一至三面：AI Coding、证据校验与长文档

原页发布时间（北京时间）：2026-10-07T11:53:54+08:00。面试完整年月日未确认，原文只列月日的地方不补年份。

根据公开候选人自述整理；岗位和面试经历未获外部认证。简答为教学整理，不是作者现场作答。一至三面合为一个流程、一篇记录；被作者拒绝的其他部门邀约不算实际面试。

<details data-knowledge-key="agent-coding">
<summary>（1）怎样审查 AI 生成的长技术方案，并决定实现顺序？</summary>
</details>

先把需求、输入输出、约束和可验收结果提取成清单，再核查方案中的假设、关键数据流、依赖与失败路径。优先做能验证核心业务的最小闭环，保留明确接口和检查点；权限、数据一致性、异常与回滚等重要边界不能因文档太长跳过。用实际代码、测试和差异证明方案可行，不能把文字完整或另一个模型认可当作交付通过。原帖未提供完整合同审核任务，这里是审查方法。

<details data-knowledge-key="agent-eval-framework">
<summary>（2）怎样验证 Agent 报告里的关系判断是否正确？</summary>
</details>

先定义任务单位、允许证据和关系标注规则，用固定案例及人工复核的参考结果建立基线。逐项检查关系两端、类型与证据支持，区分正确、错误、遗漏和无法判断，并按难度与失败类型切片。模型评审只能辅助，需和人工判断校准；保留输入、来源及模型和流程版本，复核差异后再决定修改。原帖没有质量数据，不能据展示结果认定准确率。

<details data-knowledge-key="context-engineering">
<summary>（3）长文档超过上下文窗口时，怎样分步处理并保持证据关系？</summary>
</details>

保存原文和稳定的文档版本、段落位置，按结构与任务需要切分，跨段引用保留可继续检索的标识。先定位相关片段，再让各步骤返回带来源的结构化结果，汇总仍超限时继续按任务压缩或分层处理；不能把所有摘要再次堆满窗口。把已确认约束、实体与未解决关系单独维护，核查压缩遗漏、否定和跨块冲突，必要时回读原文。子Agent与长窗口本身都不保证完整性，需用跨块和长文档案例验收。

<details data-knowledge-key="rag-citation-grounding">
<summary>（4）怎样约束 Agent 基于证据作答，并处理评审模型也会出错的问题？</summary>
</details>

把结论拆成可核查声明，绑定允许来源的具体版本和片段，先检查实体、数值、引用是否存在，再检查证据是否支持该关系。规则、数据库约束和人工复核可承担确定性检查；模型评审用于需要语义判断的部分，并在人工标注集上校准，保留不确定出口。证据不足时缩小结论、澄清或拒答，不能让生成模型和评审模型互相认同就视为事实。原帖未提供可验证结果，不能承诺这样完全消除幻觉。

<details data-knowledge-key="mcp-protocol">
<summary>（5）CLI 与 MCP Tool 的接口层次有什么不同？</summary>
</details>

CLI以命令行参数、标准输入输出和退出状态暴露能力；MCP以客户端和服务端之间的标准交互发现、描述和调用工具。服务端可以包装已有CLI，MCP使用stdio传输也不等于任意CLI天然符合协议。选型要核已有能力的输入输出契约、权限、错误、超时、版本和集成成本，性能差异用实际调用链测量；不能按名字推定某一种一定更快。原问未公开具体工具。
