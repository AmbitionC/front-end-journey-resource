### 字节 Agent 开发一面：Skill、MCP 与后端基础（2026 年 7 月）

这轮实习一面把 Agent 项目与传统后端基础放在同一条追问链中：项目是否解决真实问题、缓存是否可靠、Skill 与 MCP 如何分工，以及 Java、网络、事务和索引基础是否扎实。

#### （1）怎样证明项目不是“练手项目”？

不要回避验证范围。先说明真实用户或模拟对象、任务频率、输入规模和约束，再给出可复现的验收集、失败样本和迭代数据。未上线的项目可以用固定 Benchmark、对照实验和使用者反馈证明价值，但不能把本地演示包装成生产流量。最重要的是讲清为什么选 Agent，而不是确定性 Workflow。

#### （2）为什么加缓存？布隆过滤器解决什么？

缓存用于降低重复计算或后端读取延迟，前提是先定义 Key、TTL、容量、更新与失效策略。布隆过滤器能用较小空间判断“元素一定不存在或可能存在”，适合拦截大量不存在 Key；它有假阳性、通常不支持直接删除，不能替代数据库。缓存击穿、穿透、雪崩和数据一致性要分别治理。

延伸阅读：[Redis 缓存策略与一致性](../../../knowledge/backend/database/redis-cache.md)。

#### （3）怎样回答 Agent 项目里最难的设计？

选一个确实改变架构的难点，例如不可靠工具、长任务恢复或上下文污染。按约束、候选方案、取舍、实现、指标和残余风险回答。好的例子应包含失败路径：超时后是否重试、写操作是否幂等、恢复从哪个检查点继续、人工何时介入，以及怎样用 Trace 复现。

#### （4）Skill 与 MCP 的边界是什么？

Skill 更像可按需加载的工作方法与资源包，告诉 Agent 何时使用、怎样执行和如何验收；MCP 是连接外部数据与工具的协议边界，负责能力发现、参数契约和调用传输。Skill 可以引用 MCP Tool，但两者不是替代关系。迁移时应先把业务流程与工具接口解耦，再决定哪些知识进入 Skill、哪些副作用留在受控服务端。

延伸阅读：[Agent Skill 设计](../../../knowledge/llm/agent/agent-skill-design.md)、[MCP / A2A 协议](../../../knowledge/llm/agent/mcp-protocol.md)。

#### （5）通用 Coding Agent 能直接替代垂直项目吗？

通用 Agent 擅长代码理解、编辑和测试，但垂直系统还包含领域数据、权限、稳定流程、审计、评测和服务等级。可把通用 Agent 作为执行组件，通过窄 Tool 与领域系统协作；涉及关键业务状态时仍由确定性代码和审批门禁负责。回答的重点是系统边界，而不是比较产品宣传。

#### （6）Spring IoC、AOP 与 Override、Overload 分别是什么？

IoC 把对象创建和依赖装配交给容器，使组件面向接口协作；AOP 把日志、事务、鉴权等横切关注点织入切点。Override 是子类以相同签名重写父类可覆盖方法，运行时多态决定调用；Overload 是同一作用域内方法名相同、参数列表不同，编译期选择。四个概念应配一个项目场景，而不是只背定义。

#### （7）浏览器打开页面会经历哪些网络步骤？

先解析 URL，查询本地、系统和递归 DNS 缓存，必要时完成 DNS 递归/迭代查询；随后建立 TCP 或 QUIC 连接，HTTPS 还要做 TLS 握手与证书校验；再发送 HTTP 请求，经过缓存、重定向和内容协商取得资源。回答还可补充连接复用、HTTP/2 多路复用和浏览器资源调度。

延伸阅读：[DNS 解析、缓存与容灾](../../../knowledge/network/others/dns-analysis.md)。

#### （8）进程、线程、幻读与索引题怎样串起来回答？

进程拥有独立地址空间和资源边界，线程共享进程内存并承担调度执行；Java 线程通常映射到操作系统线程。幻读指同一事务按条件再次查询时，结果集合出现新增或消失的行，需结合隔离级别、MVCC 和范围锁说明。索引题必须从具体 SQL 的过滤、排序、选择性和执行计划出发，不能脱离查询模式给万能索引。
