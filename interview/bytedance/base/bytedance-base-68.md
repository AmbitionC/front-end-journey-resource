<details data-knowledge-key="multi-agent">
<summary>（1）多 Agent 怎样组织输入和编排？</summary>
</details>

<p>先定义任务目标、输入、依赖与完成条件，再判断哪些分支需要独立上下文和多轮探索。固定步骤用确定性编排，独立分支可并行，后续依赖要等前置结果验证后再推进。子任务合同保存对象、约束、权限、版本与结果格式，汇总时核对证据和口径，不能只拼接自然语言。</p>
<p>教学例子：两个分支分别分析流量与支付，只有它们使用相同时间窗口与数据口径时才能合并结论。这个例子并非原帖项目的已披露业务。</p>

<details data-knowledge-key="algorithm-heap">
<summary>（2）十亿条 URL、只有 1GB 内存，怎样找出现频率最高的 100 个？</summary>
</details>

<p>先明确要求精确计数及是否允许外部存储。可按完整 URL 的稳定哈希分区到磁盘，同一 URL 落入同一分区，逐分区精确统计，再用容量为 100 的最小堆维护全局候选；分区过大时继续分区或采用外部排序。不能直接把每个不同 URL 都塞进内存，也不能把近似结构的结果冒充精确 Top-K。</p>
<p>教学例子：每个分区统计完成后把 URL 与精确次数送入同一个候选堆；哈希碰撞只使不同 URL 同桶，计数仍按完整 URL 区分。原题没有给出磁盘许可，所以应先确认这个条件。</p>
