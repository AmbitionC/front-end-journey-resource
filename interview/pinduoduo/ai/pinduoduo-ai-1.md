### 拼多多 AI Agent 岗两轮技术面：RAG、多 Agent 与系统能力（2026 年 8 月）

两轮技术面从会议转写项目一路追问到 RAG、Memory、工具可靠性、长上下文、多 Agent、操作系统和算法。回答这类面试要同时覆盖业务证据、模型机制和工程故障边界。

#### （1）会议转写 Agent 的完整链路怎样介绍？

从音视频采集、分片与降噪开始，经 ASR、时间戳和说话人对齐、文本清洗，再做议题切分、摘要、行动项提取和人工校对。说明同步/异步边界、本人负责模块、失败重试与回放。ASR 选型要比较语言、领域词、实时率、准确率、成本、隐私和供应商锁定。

#### （2）ASR 和转写质量怎样评估？

基础指标可用字错率或词错率，但业务还关心专有名词、说话人、时间戳、行动项遗漏和摘要事实性。建立覆盖噪声、口音、多人打断和行业词的标注集，按场景切片。可用热词、领域词典、后处理纠错和人工反馈改善，但必须区分“转写正确”和“摘要正确”。

#### （3）语音、视频和文本怎样保护隐私？

传输与存储加密，租户与会议维度做授权，服务间使用短期凭证；原始媒体、转写和向量索引分别设置保留期与删除能力。日志默认脱敏，评测集需重新授权或匿名化。模型和外部 ASR 只能收到必要字段，所有访问和导出保留审计记录。

#### （4）RAG 的 Chunk 和评测怎样设计？

按语义边界、标题层级和文档类型切分，保留来源、权限、时间与位置元数据；用真实问题比较 Chunk 大小、重叠、Embedding、Top-K、混合检索和 Rerank。离线观察 Recall@K、MRR/nDCG，端到端观察答案正确性、引用覆盖和拒答质量。不同文档类型可以使用不同策略。

#### （5）Memory 与 Tool 可靠性怎样落地？

短期记忆保存当前任务状态与最近证据，长期记忆保存跨会话仍有价值的事实；写入要去重、版本化并可过期。工具成功率应按“正确选择、参数有效、执行成功、结果被正确使用”分段统计。超时用分阶段预算和有限重试，脏结果做 Schema/业务校验，副作用调用用幂等键防重复。

#### （6）进程、线程、协程、并发和并行怎样区分？

进程提供资源与故障隔离，线程共享地址空间并由内核调度，协程是用户态可挂起任务，适合大量等待型工作。并发描述多个任务在重叠时间推进，并行表示同一时刻真的在多个执行单元运行。选择要考虑 CPU/IO 类型、隔离、通信、调度和故障影响。

#### （7）Token、Self-Attention 与长上下文怎样串起来？

Tokenizer 把文本编码为词表 ID；Self-Attention 用 Query 与 Key 的相似度计算权重，再聚合 Value。上下文变长会增加预填充计算、KV Cache、延迟和成本，还可能出现注意力稀释与 Lost in the Middle。工程上用信息选择、分层摘要、检索和任务状态外置，而不是只依赖更大窗口。

#### （8）SFT、PPO、DPO 与 GRPO 的侧重点是什么？

SFT 用示范数据学习目标任务与输出格式；PPO 通过奖励模型和在线采样优化策略，但系统复杂；DPO 直接从偏好对学习，无需显式在线 RL；GRPO 使用组内相对奖励估计优势，常用于推理能力训练。面试回答应说明数据、训练稳定性、计算成本和适用目标，不要把它们当成互斥版本号。

#### （9）多 Agent 怎样分工、共享状态和仲裁？

按上下文、权限或专长划分角色，由中心协调者创建任务、定义验收并汇总。共享状态使用带版本的检查点，子 Agent 只写自己的产物；冲突由规则、验证器或可信证据排序处理，关键决策升级人工。若拆分不能降低上下文或提升并行度，单 Agent/Workflow 更简单。

#### （10）线上资源异常和算法题怎样准备？

CPU 飙高先看负载、线程栈、火焰图和系统调用；内存增长看 RSS、堆、直接内存、映射和泄漏趋势。`mmap` 把文件映射到虚拟地址空间，`writev` 聚合多个缓冲区减少系统调用。Top-K 常用容量为 K 的小根堆，时间 `O(n log k)`；LRU 用哈希表加双向链表实现均摊 `O(1)`。
