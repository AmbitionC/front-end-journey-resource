### 淘宝闪购 Agent 算法一面：框架选型、人工接管与线上安全（2026 年 4 月）

这轮一面围绕 Agent 工程项目追问框架选型、Human-in-the-Loop、高风险操作、长期记忆、模型层经验和线上效果排障。记录中带有较多个人项目量化描述，本文只保留可确认的题目与通用解法，不把这些数值当作事实。

#### （1）怎样在 SDK 与开源 Agent 框架之间选型？

先比较任务编排、工具协议、状态恢复、可观测性、扩展成本和社区维护，再评估数据是否能出域、依赖是否可审计、模型能否替换及部署成本。SDK 上手快不等于适合生产，开源也不自动等于安全。应通过最小真实任务验证关键路径，并为供应商锁定和版本升级预留适配层。

#### （2）怎样设计 Human-in-the-Loop？

在不可逆写入、低置信度决策、权限提升和高金额操作前创建检查点，把计划、参数、证据和影响范围展示给审批人。审批结果要绑定状态版本，避免等待期间环境变化后执行旧动作；拒绝、修改和超时都要有明确分支。模型写下“需要确认”只是提示，真正的暂停必须由编排器和权限层强制执行。

延伸阅读：[Human-in-the-Loop](../../../knowledge/llm/agent/agent-human-in-loop.md)。

#### （3）高风险在线环境怎样管控 Agent 异常？

按只读、可逆写入和不可逆操作划分工具权限，默认最小授权；用参数 Schema、策略引擎和业务校验阻止越权。运行时设置超时、最大步数、失败熔断和费用预算，在沙箱或仿真环境先执行高风险流程。所有动作记录操作者、输入、状态版本、结果与审批证据，便于追责和回放。

延伸阅读：[Agent 权限模型](../../../knowledge/llm/production/agent-permission-model.md)、[Agent 沙箱](../../../knowledge/llm/agent/agent-sandbox.md)、[Agent 审计日志](../../../knowledge/llm/production/agent-audit-log.md)。

#### （4）间隔数周后继续的长周期会话如何管理？

近期对话保留原文，已完成过程压缩成摘要，稳定事实和用户偏好结构化存储，外部资料只保留可重取引用。新会话根据当前目标检索少量相关记忆，并附时间、来源与置信度；冲突时保留版本或请求确认。不能把全部历史塞入上下文，也不能让未经验证的模型总结成为唯一事实源。

延伸阅读：[Agent 记忆架构](../../../knowledge/llm/agent/agent-memory-architecture.md)。

#### （5）比较两种 Agent 记忆方案时看哪些维度？

应比较写入触发、记忆类型、索引方式、压缩粒度、召回与重排、冲突处理、遗忘机制、隐私隔离和可审计性。不要根据产品名称推断内部实现，也不要只比较“是否使用向量库”。最终要用长对话任务测试信息保留率、错误记忆率、召回成本和对任务完成率的影响。

#### （6）Agent 还有哪些优化空间，怎样排优先级？

先从真实失败轨迹统计最大损失来源，例如检索遗漏、工具误选、参数错误、循环或结果未验证，再按影响、频率和改造成本排序。能用校验、路由和状态机解决的问题不应立即训练模型。若确实需要反馈学习，也必须先有稳定任务定义、可信奖励和离线评测，避免把线上噪声放大。

#### （7）怎样回答 SFT 或模型层工作经验？

按任务、数据、基座模型、目标函数、训练配置、验证集和部署影响说明。多任务微调要解释不同损失如何加权，防止一个任务压制另一个；同时检查数据泄漏、类别不平衡和过拟合。如果经验只停留在 API 调用，应如实说明，并把工程侧能力与模型训练能力分开。

#### （8）Agent 工程方案的差异化体现在哪里？

模型和框架相同不代表系统效果相同。差异通常来自受控工具集合、严格输入输出校验、任务状态与恢复、权限、安全门禁、领域检索和评测闭环。任何“降低成本”或“减少轮次”的结论都应给出相同任务集、基线、样本量和统计口径，不能用单次演示证明。

延伸阅读：[工具结果校验、解析与反馈](../../../knowledge/llm/agent/agent-tool-result-validation.md)、[Agent 失败恢复](../../../knowledge/llm/production/agent-failure-recovery.md)。

#### （9）本地 AUC 较高而线上显著下降，应该怎样排查？

先确认线上模型、特征 Schema、预处理和缺失值策略与训练一致，再比较特征分布、预测分布和分群指标。随后排查时间穿越或特征泄漏、训练与线上样本选择偏差、标签口径与延迟、模型版本错误及推理精度变化。用同一批请求离线回放线上特征可以快速区分数据、模型和 Serving 问题，修复后通过灰度与监控验证。

延伸阅读：[Feature Store](../../../knowledge/data/analysis/feature-store.md)。

#### （10）面试中如何说明技术选型的取舍？

先给业务约束和备选方案，再从正确性、安全、成本、时延、团队能力和可维护性比较，说明为什么当前阶段选择某个方案，以及什么条件变化时会重新选型。面试官追问“为什么”时应给证据或实验，而不是把熟悉程度包装成技术优势。
