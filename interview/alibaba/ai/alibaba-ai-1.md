### 阿里云 Agent 开发秋招一面（2026 年 8 月）

这轮一面集中考查 AI Coding、Agent Skill、Harness、工具调用、子 Agent 和 Agent Loop，并安排了现场 AI Coding。公开记录没有披露现场题目，本文保留这一事实，不虚构题面。

#### （1）自我介绍和项目经历怎样组织？

用一分钟说明目标岗位、两项最相关能力和一个可验证项目，再按“问题—约束—方案—本人贡献—结果”展开。学习经历只需说明与岗位的关联，不展开可定位到个人的细节。项目被追问时主动给出失败案例、取舍和指标，让面试官能区分亲自实现与简单使用。

#### （2）平时怎样用 AI 辅助编码？

可按需求澄清、代码检索、实现、测试和 Review 分阶段回答。先给模型最小必要上下文与验收标准，要求小步修改；随后独立运行类型检查和测试，复核安全、性能及边界条件。涉及迁移、删除、生产数据或凭据的操作必须由人确认。价值应由交付周期、缺陷率和返工量衡量，而非“用了多少工具”。

#### （3）什么是 Agent Skill，怎样比较和编写 Skill？

Skill 是面向一类任务的可复用操作说明及配套脚本、参考资料或模板。比较不同 Skill 时看触发边界、输入输出契约、渐进式披露、失败处理、权限和可验证性。自己编写时要把流程写成可执行步骤，明确禁止事项和完成标准，复用确定性脚本，并用真实任务验证不会误触发或漏步骤。

延伸阅读：[Agent Skill：渐进式披露、热插拔与版本治理](../../../knowledge/llm/agent/agent-skill-design.md)。

#### （4）怎样评价新的 Agent 产品或比较两种 Coding Harness？

先基于当时的一手文档和实际任务复现，不用产品热度代替结论。比较维度包括模型是否可替换、上下文获取、工具与权限、任务循环、检查点、子 Agent、扩展机制、可观测性和运行成本。源码追问应讲清入口、状态模型、工具执行与事件流；没读过的部分明确边界，不能凭界面行为推断内部实现。

#### （5）一个可靠的 Harness 必须具备什么？

Harness 要把模型决策连接到真实环境，并约束执行：统一消息与工具协议，管理上下文和状态，传播取消/超时，隔离文件与网络权限，记录可回放轨迹，并提供测试、审批和预算门禁。它还要定义错误分类和恢复点，使任务失败后能安全继续，而不是从头重复副作用。

#### （6）Agent 有哪些工具调用方式，怎样保证按需调用？

常见方式有模型原生 Function Calling、MCP 工具、受控命令或应用内部 API。无论入口如何，都要提供清晰的名称、用途、输入 Schema、错误语义和权限范围。工具很多时先按意图与权限召回候选；执行前校验参数和副作用，执行后验证结果。无工具也能直接回答时，不应为了展示流程强制调用。

延伸阅读：[Function Calling 与工具调用](../../../knowledge/llm/dev/function-calling.md)、[工具发现、选择与路由](../../../knowledge/llm/agent/agent-tool-selection.md)。

#### （7）为什么需要子 Agent，什么时候启用？

当子任务可独立完成、需要隔离上下文或专业工具，并且并行收益大于协调成本时适合启用。主 Agent 必须给出范围、输入、输出格式和验收条件；子 Agent 不应自行扩大权限。简单顺序任务、共享状态频繁变化或多人会修改同一目标时，直接在主流程完成往往更稳。

延伸阅读：[Subagent 子智能体设计](../../../knowledge/llm/agent/agent-subagents.md)。

#### （8）Agent 之间如何通信？

可以使用 Agent-as-Tool 的请求响应、事件队列、共享状态或显式 handoff。消息应带 taskId、发送者、状态版本、证据和截止时间，并定义确认、重试与幂等。共享大段聊天记录既浪费上下文又难审计，最好传结构化结果和可回溯引用；最终责任仍由协调者收敛。

#### （9）设计 Agent Loop 要注意什么？

循环依次读取状态、选择动作、执行、校验并提交新状态。必须设置成功判据、最大步数、Token/时间/费用预算，识别重复动作，对可重试与永久错误分别处理；写操作使用幂等键，高风险动作进入人工审批。保存模型输入、工具参数、结果摘要和状态版本，才能复现问题与断点续跑。

延伸阅读：[Agent Run Loop、轮次与终止条件](../../../knowledge/llm/agent/agent-run-loop.md)。

#### （10）现场 AI Coding 应怎样完成？

由于记录没有具体题目，不能补造实现。通用作答流程是先复述需求与约束，检查现有代码和测试，提出最小方案，再小步修改并持续运行验证；完成后说明边界、复杂度和未覆盖风险。使用 AI 时仍要能逐行解释关键代码，并对最终结果负责。
