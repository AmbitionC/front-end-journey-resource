这一章先把 RSI 这个词讲清楚：它是什么，从哪里来，现在工程上到底在改什么，以及它做不到什么。后面十章做的每一件事，都能在这一章里找到位置。

## 一句话讲清 RSI

RSI 是 Recursive Self-Improvement 的缩写，中文叫递归自我改进：**一个系统自己提出对自己的修改，验证修改确实有用，把它留下来，然后从改过的版本出发接着改。**

三个词各管一件事：

| 词 | 含义 | 少了它会怎样 |
|---|---|---|
| 自我 | 修改是系统自己提出的，不是人写的 | 那就是普通的人工调优 |
| 改进 | 修改要经过验证，确实变好才留下 | 那就是随机改动 |
| 递归 | 下一次修改从上一次改过的版本出发 | 那就是只优化了一次 |

项目一做出来的编程 Agent 上线之后，你大概已经干过这件事的人工版本：看失败记录，猜原因，改提示词，再跑一遍看有没有变好。RSI 把这个循环里的人换成了 Agent 自己，你只负责定规矩：什么算变好，什么不许碰。

## 从一个设想到一套工程做法

这个概念不是这两年才有的，但它是这两年才变得能动手做的。四个节点串起来是这样：

| 时间 | 工作 | 怎么保证改了之后是变好 | 结果 |
|---|---|---|---|
| 2003 | Gödel Machine（Schmidhuber） | 先用数学证明这次修改有益，证出来才改 | 理论上最优，实际上证不出来，没法落地 |
| 2023 | STOP（Zelikman 等） | 让一段调用模型的脚手架程序改进它自己，用下游任务的分数来比 | GPT-4 能把自己的脚手架改好；GPT-3.5 和 Mixtral 越改越差 |
| 2025 | Darwin Gödel Machine | 放弃证明，改成在编程基准上实测，并保留一个历代版本的档案库 | SWE-bench 从 20.0% 到 50.0%，Polyglot 从 14.2% 到 30.7% |
| 2026 | Meta-Harness、Self-Harness、RRSI 等 | 把修改对象收窄到 Agent 的外壳，把验证做成固定的闸门 | 同一个模型，只换外壳，在留出任务上也有提升 |

这条线上真正的转折是第三步：**用实测代替证明。** Gödel Machine 要求先证明再修改，这个门槛高到几乎没有修改能过；Darwin Gödel Machine 的做法是改完直接去考试，分数涨了就留下。从这一刻起，RSI 成了一个评测问题：只要你有一把量得准的尺子，就能让系统在这把尺子下面自己试。

这也是本项目把评测和进化放在一起、并且先讲评测的原因。

STOP 那一行值得多看一眼。它的论文摘要里自己写明了这“不是完整的递归自我改进”，因为模型本身没有变；同时它留下了一个很实在的观察：弱一些的模型在这个循环里会退化。这两点后面讲边界时都会用到。

## 现在说的 RSI，改的是外壳

听到“自己改自己”，第一反应往往是模型在改自己的权重。目前主流的做法不是这样：**模型是冻结的，被改的是包在模型外面的那一层外壳（harness）。** 提示词、记忆、工具、流程、控制代码，都属于外壳。

Lilian Weng 在 2026 年 7 月的一篇博客里，把可以改的对象从浅到深排成了一个阶梯：指令提示词、结构化的上下文、工作流、外壳代码、优化器自己的代码。本项目的四个级别正好落在这个阶梯的前四格上：

![RSI 能改的对象从浅到深分五格：指令提示词、结构化上下文、工作流与配置、外壳代码、优化器自己的代码；本项目的四级进化对应前四格，分别是改系统提示词、维护经验手册、调配置与工具、改外壳代码；第五格改进改进器本身，本项目不做](https://font-end-journey-resources.oss-cn-hangzhou.aliyuncs.com/images/project-ee-rsi-ladder-v1.dark.png)

*图：越往右，能改的东西越多，改坏的风险也越大。本项目做到第四格。*

| 阶梯上的一格 | 本项目的哪一级 | 改的是什么 | 章节 |
|---|---|---|---|
| 指令提示词 | 第一级 | 系统提示词里的规定 | 08 |
| 结构化上下文 | 第二级 | 一本逐条增补的经验手册 | 09 |
| 工作流 | 第三级 | 轮次上限、可用工具、提醒时机这些配置 | 10 |
| 外壳代码 | 第四级 | 处理工具结果的那段代码 | 11 |
| 优化器自己的代码 | 不做 | 提出修改的那个程序本身 | |

最后一格是“改进那个负责改进的程序”，STOP 和 Darwin Gödel Machine 研究的就是它。它离“递归”这个词的本意最近，也最难控制。本项目的提案器是固定的四个，不会改自己，这一点面试时要主动说清楚。

## 一轮改进的四步

2026 年 11 月有一篇综述性质的论文（Shah 与 Kathrotia）把这一类工作的共同结构总结成一个四步循环：诊断失败、提出修改、验证候选、部署更新。本项目的源码和它一一对应：

| 步骤 | 做什么 | 源码位置 |
|---|---|---|
| 诊断 | 读失败轨迹，把失败归到具体的外壳组件上 | `evo/evolve/diagnose.py` |
| 提案 | 针对归因提出一处修改 | `evo/evolve/` 下四个级别各一个文件 |
| 验证 | 换一批没见过的题考试，旧题不能退步 | `evo/evolve/gate.py` |
| 部署 | 通过的版本成为当前版本，没通过的留档 | `evo/store.py` |

那篇论文摘要里还有一个和本项目直接相关的结论：把整个外壳一次重写，容易过拟合，也容易在模块之间互相弄坏；按模块小步修改、每一步过闸门，效果更好，花的 token 也少得多。本项目每一代只改一处，就是这个取舍。

## 递归：一代接一代

只跑一轮，是“自我改进”。把合入的版本当成下一轮的起点接着跑，才是“递归”。源码里对应的是 `evolve --generations N`：

```bash
python -m evo.cli --store runs-tight evolve --generations 5 --seed tight -n 1
python -m evo.cli --store runs-tight tree
```

规则很少：

- 每一代只改一级。这一级改成了，下一代接着改它；被拦下或者提不出修改，下一代换下一级。顺序是提示词、配置、经验手册、外壳代码。
- 合入的版本成为下一代的起点。被拦下的候选不会生效，但留在版本树上，能看到它当时考了多少分、为什么没过。
- 连着一圈都没有合入，说明在这套题上已经改不动了，自动停下。

![在线试用里那次五代运行的版本树：起点版本新题通过率 56%，第 1 代改提示词没涨分被拦下，第 2 代调配置涨了分但用量超标被拦下，第 3 代补经验手册考到 89% 上线成为新的当前版本，第 4 代再改手册分数反而下降被拦下，第 5 代改外壳代码试跑出错被拦下；被拦下的候选留在旁支上不生效](https://font-end-journey-resources.oss-cn-hangzhou.aliyuncs.com/images/project-ee-rsi-generations-v1.dark.png)

*图：下面那次五代运行的版本树。实线是上线的版本链，旁支是被拦下的候选；下一代永远从链上最后一个版本出发。*

在线试用里第一个场景就是一次真实的五代运行，用的起点是 `tight`：最简的提示词，轮次上限压到 6，工具结果只留 500 字。这是刚上线、为了省用量把参数压得很紧时常见的样子。那一次的记录是：

| 代 | 改哪一处 | 它发现了什么 | 候选在新题上考了多少 | 结果 |
|---|---|---|---|---|
| 起点 | | | 56% | |
| 1 | 系统提示词 | 轮次都耗在被拒绝的命令上，提示词没交代这个环境的限制 | 56%，没涨 | 拦下：新题没有变好 |
| 2 | 外壳配置 | 失败的任务都是轮次用完了还没改完，把轮次上限从 6 提到 12 | 89% | 拦下：分数涨了，但平均用量是原来的 1.6 倍，超过 1.5 倍的上限 |
| 3 | 经验手册 | 提炼出 4 条经验，比如少用会被拒的组合命令、改完必须跑一次测试 | 89% | 上线，回归集 4 条无退步 |
| 4 | 经验手册 | 又补 1 条、改写 1 条 | 67%，反而降了 | 拦下：新题没有变好 |
| 5 | 外壳代码 | 想把报错的关键行提到工具结果最前面 | 没进考场 | 拦下：代码试跑就出错，少了一行导入 |

五代下来，新题通过率从 56% 到 89%：上线 1 次，拦下 4 次，四次的理由各不相同。

这张表里有三件事值得带走：

1. **涨分只来自其中一代。** 五次修改里真正站得住的只有一次，其余四次看起来都有道理，考完才知道不行。没有闸门，这四次都会上线。
2. **被拦下的修改和合入的修改一样重要。** 第 2 代最有代表性：把轮次上限翻倍，分数和第 3 代一样涨到了 89%，但它是拿用量换来的，闸门的成本规则把它挡了回去；下一代换了一种不多花钱的改法，同样的分数就过了。第 4 代说明“再多改一点”不一定更好，第 5 代说明模型写的代码要先试跑。
3. **同样的命令你再跑一遍，结果不会一模一样。** 模型的输出有随机性。我们定稿前后一共跑过三次：一次从 56% 到 100%，一次从 67% 到 78%，放上来的这一次是 56% 到 89%，连起点的分数都会差一道题。验收集只有 9 条，一道题就是 11 个百分点，所以这些数字只能说明流程是通的，不能当成效果结论。稳定的是规矩：没考过的不上线。

## 必须讲清的四个边界

RSI 这个词容易让人想到“智能爆炸”。面试时讲这个项目，主动把边界讲清楚，比把效果讲得很大更有说服力。

**它是有界的。** 模型冻结，能改的只有外壳，所以上限由模型本身的能力和这套题决定。上面那次运行里，五代只有一代站得住，后两代都没能再往上走。它是一个会收敛的优化过程，不会无限变强。

**它会过拟合。** 每一代的修改都是照着练习题的失败提出来的，代数一多，修改会越来越贴着那几道题。RRSI 这篇论文专门处理这个问题：限制每个候选能改多少、筛掉只对某道题有用的修改、涨幅没超过噪声的不收，摘要报告的结果是在没见过的基准上分数也更高，策略占用的 token 比不加约束的进化少 30%。本项目的编辑预算是它的一个简化版，在第 12 章。

**它会作弊。** 系统优化的是分数，不是你心里想的那个目标。评分器有漏洞，它迟早会找到，比如删掉失败的测试、只声称修好了。所以审计评分器（第 07 章）必须排在进化之前，提案器也永远看不到考试用的那批题。

**弱模型会退化。** STOP 的实验里，GPT-4 能把脚手架越改越好，GPT-3.5 和 Mixtral 却越改越差。提出一个好修改本身就需要能力，模型不够强时，这个循环放大的是噪声。换一个更小的模型来跑本项目，看到分数不涨甚至被闸门连续拦下，是合理的结果，照实写。

## 面试常见追问

- **RSI 是什么？和 AutoML、提示词优化有什么区别？** 讲三个词：自己提出修改、验证后才留下、从改过的版本接着改。提示词优化只动阶梯的第一格，RSI 关心的是整个外壳，并且强调一代接一代。
- **模型的权重变了吗？** 没有。模型冻结，改的是外壳。能说出阶梯上的五格，以及自己做到了哪一格。
- **Gödel Machine 和 Darwin Gödel Machine 差在哪？** 前者要求先证明修改有益，后者改成实测并保留历代版本。转折点是用实测代替证明。
- **怎么保证它不是越改越差？** 准入闸门：换一批题考试、旧题不能退步、成本不能失控；连续多代时再加编辑预算。被拦下的候选不生效但留档。
- **它会不会无限变强？** 不会。讲有界、过拟合、作弊、弱模型退化这四条，最好带上自己跑出来的那张表：五代里真正上线的没几代。
- **你做的和论文差多少？** 规模小得多，提案器不改自己，编辑预算是简化版。结论只对自己的任务集成立。
