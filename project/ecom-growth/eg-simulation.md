闭环需要反馈：素材投出去，有人看、有人点、有人买。个人项目没有真实流量，这一章搭一个模拟的试投环境来提供反馈，并且把它的可信边界讲清楚。这是整个项目里最需要诚实的一章。

## 模拟环境要做什么

输入一版素材和一个模拟用户，输出这个用户的反应：

```python
@dataclass
class Reaction:
    clicked: bool
    ordered: bool
    feedback: str        # 一句话的理由，用于归因和改写
```

把素材分发给一批模拟用户，汇总他们的反应，就得到一轮“试投数据”。

## 模型能模拟真实用户吗

先看已有的研究怎么说。

**有专门检验这个问题的数据集。** OPeRA 是一个从真实参与者的网购过程中采集的数据集，用问卷和浏览器插件记录了用户画像、页面观察、细粒度的网页操作，以及用户自己当场写下的操作理由。它定义的任务是：给定一个用户的画像和此前的观察、操作、理由，预测这个用户的下一步操作和理由。数据集论文把它称为第一个用于这类评测的公开基准。

**后续工作在这个基准上训练专门的模型。** Customer-R1 用强化学习、以操作是否正确作为奖励，训练按用户画像逐步模拟购物行为的模型，报告的结果是明显优于只靠提示词和监督微调的基线。

这两项工作放在一起，传递的信息是：只用提示词让通用模型扮演购物者，离真实行为有差距，这个差距大到值得专门建数据集、专门训练模型去缩小。

**真实的线上验证是另一回事。** Meta 发表过一项工作，用历史广告的效果数据作为奖励信号训练广告文案生成模型，然后在 Facebook 上做了为期 10 周的线上 A/B 测试，覆盖近 3.5 万个广告主和 64 万个广告变体，报告点击率相对一个监督模仿基线提升了 6.7%。这才是“证明文案有效”的标准做法：真实流量上的对照实验。

本项目做不到这一点。所以结论要摆在前面：**模拟环境能验证闭环的工程是否正确，不能证明素材对真实用户有效。**

## 模拟用户的两种做法

| | 纯模型扮演 | 行为模型加模型扮演 |
|---|---|---|
| 做法 | 把人物设定和素材交给模型，问它点不点 | 用一个带参数的概率模型决定点击和下单，模型只负责判断“相关程度”和给出理由 |
| 优点 | 实现简单，反应带有文字理由 | 点击率的整体水平可控，结果可复现 |
| 缺点 | 模型普遍过于“配合”，点击率高得不真实；同样的输入结果不稳定 | 概率模型的参数是你设定的 |

本项目用第二种。原因是纯模型扮演有两个很难克服的毛病：它太好说话，问十次有八次说会点；并且它对文案的偏好反映的是模型自己的文字品味，而不是用户的。

## 行为模型

把一次反应拆成两步：

![模拟用户的一次反应拆成两步：模型先给素材和这个用户的动机、顾虑的相关程度打分，三个维度各 0 到 2 分；概率模型再结合相关程度和用户的行为特征算出点击概率，按概率抽样决定点或不点；点了的用同样方式算出下单概率并抽样，最后生成一句理由](https://font-end-journey-resources.oss-cn-hangzhou.aliyuncs.com/images/project-eg-simulation-two-step-reaction-v1.dark.png)

*模型只负责打相关程度的分，点不点由概率模型和抽样决定。*

模型只做它相对擅长的事：阅读理解。它回答三个具体的问题，每个问题只有三档：

```text
用户设定：{persona}
素材：{body}

分别判断（每项回答 0、1 或 2）：
1. 素材是否提到了这个用户在意的点？（0 没提到，1 沾边，2 正好说中）
2. 素材是否回应了这个用户的顾虑？（0 没有，1 部分，2 明确回应）
3. 素材中是否有这个用户反感的说法？（0 没有，1 有一点，2 明显）

然后用这个用户的口吻写一句话，说明对这条素材的第一反应。
```

点不点由一个简单的概率模型决定：

```python
def click_prob(rel: Relevance, user: SimUser, base_ctr: float) -> float:
    lift = 0.6 * rel.motive + 0.4 * rel.concern - 0.8 * rel.aversion   # 各项 0 到 2
    logit = math.log(base_ctr / (1 - base_ctr)) + lift + user.noise
    return 1 / (1 + math.exp(-logit))

def order_prob(rel: Relevance, user: SimUser, base_cvr: float) -> float:
    p = base_cvr * (1 + 0.5 * rel.concern) * user.behavior["buy_per_pv_scaled"]
    return min(p * (1 - 0.3 * user.price_sensitivity), 1.0)
```

几点说明：

- `base_ctr` 和 `base_cvr` 是基准点击率和转化率。它们决定了整体水平，由你设定为一个符合常识的较低数值，而不是由模型的“热情程度”决定。
- 系数 0.6、0.4、0.8 是本项目给的起步值，没有实证依据。它们表达的是一个假设：说中动机比回应顾虑的影响大，引起反感的影响最大。
- `user.behavior` 来自真实行为数据。`buy_per_pv_scaled` 是这个用户的 `buy_per_pv` 除以全体用户的平均值，平均水平的用户取 1。一个在真实数据里看一百次才买一次的用户，在模拟里下单概率也低。这是模拟环境里唯一有真实依据的部分。
- `user.noise` 是每个用户固定的随机偏移，表示个体差异。

把假设写成显式的公式，好处是任何人都能看到这个环境是怎么运转的，并质疑其中任何一项。

## 三个必须处理的问题

### 循环论证

人群是模型定义的，素材是模型针对这些人群写的，再让模型去判断素材和人群是否相关。这三步用同一个模型，等于自己出题、自己答题、自己判卷。

缓解办法：

- **扮演和生成用不同的模型。** 判断相关程度的模型，和写素材的模型来自不同的厂商。
- **隐藏一部分用户属性。** 构造模拟用户时，给每个人加上素材生成环节不知道的属性，例如“对夸张语气反感”“只在乎价格”。这些隐藏属性参与相关程度的判断。这样素材不可能完全对着答案写，环境里存在需要靠试投才能发现的信息。
- **加入不相关的用户。** 模拟用户池里放一部分根本不属于任何目标人群的人，他们对所有素材反应都很弱。

第二条是关键。没有隐藏信息的环境里，优化只是在验证模型的自洽，试投学不到任何新东西。

### 结果要可复现

- 模型打分的结果按“素材内容和用户编号”缓存，同一对组合只打一次分。
- 抽样用固定的随机种子。
- 环境的全部参数（基准率、系数、隐藏属性的分布）存成一份配置，和每一轮的结果一起记录。

可复现还带来一个好处：进化环节改写出一版新素材时，其他素材的结果不变，对比才有意义。

### 环境本身要检验

用「Agent 评测与自进化平台」项目的思路，拿已知答案去考这个环境：

| 检验 | 做法 | 期望 |
|---|---|---|
| 无关素材 | 把另一个品类的素材投给这些用户 | 点击率接近基准的下限 |
| 违背顾虑的素材 | 故意强调用户反感的点 | 明显低于正常素材 |
| 对症素材 | 人工针对某类人群的动机和顾虑写一版 | 在该人群上明显高于其他人群 |
| 重复运行 | 同一批素材换一个随机种子再跑 | 排序基本一致 |

四项都符合期望，只说明这个环境的行为是合理且自洽的，不说明它接近真实用户。

## 在看板和报告里怎么标注

所有出现效果数字的地方，都带上固定的说明：

```text
以下数据来自模拟试投环境（配置 sim-v3，模拟用户 2000 人，随机种子 42）。
模拟用户的行为特征抽样自公开数据集，人群设定与偏好为合成。
这些数字用于比较素材之间的相对表现，不代表真实投放效果。
```

报告只讲相对关系：“在这个环境里，A 比 B 好”。不讲绝对数值：“点击率达到了多少”。

## 如果有机会接触真实数据

这一节是给以后用的。项目的结构为真实数据留了位置：

- 试投环境是一个接口。把它的实现从模拟换成真实的投放系统，上下游都不用改。
- 有真实的曝光点击日志时，第一件事是用它校准行为模型的参数，然后比较模拟环境给出的素材排序和真实排序是否一致。
- OPeRA 这类真实行为数据集可以用来检验“模型判断相关程度”这一步有多可靠。

面试时讲出这三点，说明你知道从模拟走向真实需要补什么。

## 自己动手时的检查点

1. 实现行为模型和模型打分，跑一轮 16 版素材乘 500 个用户的试投。
2. 完成四项环境检验，记录结果。
3. 加入隐藏属性，对比加入前后素材排序的变化。
4. 换一个随机种子重跑，看最优素材的排名是否稳定。

## 面试常见追问

- **没有真实流量，怎么验证效果？** 直接说明是模拟环境，再讲它的构成、做了哪些检验、能证明什么不能证明什么。
- **模型扮演用户可靠吗？** 引用真实购物行为数据集和相关研究，说明这是一个未解决的问题，以及你为此做的设计。
- **怎么证明业务价值？** 真实业务里靠线上对照实验，举 Meta 那项工作的例子；说明本项目的环境接口可以替换成真实系统。
- **模拟环境的最大风险是什么？** 循环论证，讲三条缓解办法，重点讲隐藏属性。
