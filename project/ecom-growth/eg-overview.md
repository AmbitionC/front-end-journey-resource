这个项目做一个电商营销增长助手：输入一个商品和一个增长目标，系统自己圈人群、写素材、过审核、小流量试投、看数据、淘汰差的、改写好的，一轮一轮往下跑。

## 背景：为什么做这个项目

**它是大厂里真有人在做的事。** 我们整理了牛客上公开的 Agent 岗位面经和实习分享，电商和广告方向反复出现的题目几乎就是这个项目的各个环节：

| 出处（牛客公开帖子的摘要） | 内容 |
|---|---|
| 字节 抖音增长 实习分享 | 多 Agent 的广告素材生产项目，实习生负责策略设计和评测体系，提到“评测驱动优化” |
| 美团 面试设计题 | 面向营销投放的 Agent：输入目标和预算，自动查历史方案、生成报告；追问怎么证明报告可信 |
| 字节 面试设计题 | 短视频文案生成 Agent，要求高并发下低延迟、成本可控、文案合规 |
| 美的 面试题 | 让你设计一个素材生产 Agent，你会怎么设计 |
| 小红书 实习分享 | 项目延伸到广告投放自优化 |

**它有闭环。** 客服、导购这类场景做完就是一次问答。营销投出去有数据回来，可以根据数据改，改完再投。这个闭环让评测和进化有了业务落点，后面的「RSI 自进化 Agent」项目会把这套方法系统展开。

**它不是检索问答。** 核心难点在生成、审核、决策和优化，和知识库问答是两类问题。

## 目标：做成什么

一句话的目标：**给定一个商品和一个增长目标，自动找出对每类人群最有效的卖点和写法，并且每一步都说得清依据。**

拆开来是三条要求：

1. **闭环能自己跑完。** 从理解商品到出最终报告，中间只在需要人拍板的地方停下来。
2. **合规有硬保证。** 没有通过审核的素材进不了试投，这一条由代码强制，不靠模型自觉。
3. **结论有依据。** 说“这个卖点更有效”时给出数据和区间；数据不够时写“无结论”，不硬凑。

跑起来大致是这样：

```text
> 给「清透防晒乳 SPF50+」拉新，预算 10000，目标是首单转化

● 商品理解：提取 6 个卖点，其中 2 个缺少证据已标记
● 人群分层：4 类人群（通勤白领、户外运动、敏感肌、学生党）
● 素材生成：每类人群 4 版文案，共 16 版
● 审核：规则拦截 2 版（含绝对化用语），模型判定 1 版功效表述超范围，13 版通过
  ▸ 等待确认后开始试投 [确认]
● 第 1 轮试投（预算 1500）
  敏感肌 ×「成分安全」点击率最高；学生党 ×「大容量」无明显反应
● 归因：敏感肌人群对“无酒精”反应明显，对“轻薄”不敏感
● 素材进化：淘汰 5 版，改写 4 版，送审后进入第 2 轮
……
● 第 4 轮后停止：最优组合已连续两轮稳定
  报告：report/campaign-0412.md
```

以上是目标形态的示意。所有效果数据来自模拟环境，下面会讲清楚这意味着什么。

## 要做哪些事

目标拆成五件事，对应后面的章节。每件事做完都有一个能单独演示的结果。

| 要做的事 | 章节 | 做完能演示什么 |
|---|---|---|
| 定方案 | 系统架构 | 一张讲得清的架构图：主管怎么调度各环节，环节之间怎么交接 |
| 生产素材 | 商品理解、人群分层、素材生成 | 输入商品，输出分人群的多版素材，每个卖点都标着依据 |
| 审核把关 | 合规与调性审核 | 不合规的素材被拦下并给出原因 |
| 试投与归因 | 试投环境、预算分配、效果归因 | 一轮完整的小流量试投和一份归因报告 |
| 迭代闭环与工程化 | 素材进化、工程化 | 多轮自动优化，以及成本、并发和断点续跑的控制 |

## 预期结果：做完手里有什么

配套源码是按这套设计写的一个可运行版本，做完你能拿出这些东西：

- **一条从头跑到尾的闭环。** 离线模式不需要模型密钥，几秒钟跑完整个流程；接上真模型后是一次完整的多轮活动。
- **每轮一份归因报告。** 哪个卖点、哪种写法对哪类人群有效，置信程度如何，哪些问题需要人来回答。
- **三个可以自己复现的数字。** 审核在评测集上的漏放率和误拦率；三种预算分配方式在同一环境下的对比；末轮素材相对首轮最优素材在留出用户上的提升和区间。
- **一组不需要模型的测试。** 审核闸口、预算上限、断点续跑这些硬约束都有测试守着。

源码是用来对照和兜底的。写进简历的那一版要你自己实现一遍，数字用你自己接上真模型后跑出来的结果，并且带上“模拟环境”这个前提。下一节讲为什么。

## 边界：关于数据，必须先说清楚

个人项目没有真实的用户流量，也没有平台的投放系统。本项目的做法是搭一个模拟的试投环境：用公开的电商用户行为数据构造一批模拟用户，由模型扮演他们对素材作出反应。

这带来三条贯穿整个项目的约束：

1. **所有效果数字都是模拟结果。** 点击率、转化率、提升幅度，都只在这个模拟环境里成立，不能当成真实投放效果来讲。
2. **模拟用户不等于真实用户。** 模型能在多大程度上模拟一个真实购物者，本身是一个还在研究中的问题，已经有团队专门采集真实购物行为数据来检验这一点。模拟环境一章会介绍相关的数据集和研究。
3. **项目的价值在于闭环本身。** 你要展示的是：怎样把一个营销任务拆成可执行的环节、怎样保证合规、怎样做探索和分配、怎样根据反馈改进，以及你清楚模拟和真实之间差在哪里。

**这是一个个人项目，简历上要写成个人项目。** 不要把它包装成某家公司的实习经历。面试官问两句就能分辨，而且一个把边界讲得清清楚楚的个人项目，比一段经不起追问的经历有价值得多。

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11 及以上 | 与另外两个项目一致 |
| 编排 | 「从零手写通用 Agent」项目的内核，主管加子任务 | 也可以独立实现，只需要执行循环和子任务调度 |
| 服务 | FastAPI | 提供看板接口和人工确认接口 |
| 存储 | PostgreSQL | 素材、人群、投放日志之间有大量关联查询 |
| 看板 | 一个单页应用 | 展示每轮的人群、素材、数据和结论 |
| 行为数据 | 公开的电商用户行为数据集 | 用来构造模拟用户的行为特征 |

配套源码为了拿到手就能跑，在几处做了简化，源码的说明文件里有一张对照表。比较要紧的有四处：用 SQLite 代替 PostgreSQL；用命令行确认代替看板；编排是独立实现的，没有复用通用 Agent 的内核；随附的行为数据样例是合成的，想让行为分布有真实依据，要自己换成真实数据集。
