同一款防晒，对通勤的人该讲轻薄不搓泥，对跑步的人该讲防水防汗。人群分层决定了后面每一版素材对谁说、说什么。这一环节用公开的行为数据和商品卖点，划出几类目标人群，并构造一个模拟用户池供试投使用。

## 这一环节产出两样东西

| 产物 | 给谁用 | 内容 |
|---|---|---|
| 人群定义 | 素材生成、归因 | 几类目标人群，每类的特征、动机、顾虑 |
| 模拟用户池 | 试投环境 | 几百到几千个模拟用户，每个属于某类人群，带个体差异 |

## 行为数据从哪里来

本项目使用公开的电商用户行为数据集。一个常用的选择是阿里天池上公开的淘宝用户行为数据集：约一亿条行为记录，来自约一百万名用户，时间范围是 2017 年 11 月 25 日到 12 月 3 日，每条记录包含用户编号、商品编号、类目编号、行为类型和时间戳，行为类型有浏览、加购、收藏、购买四种。数据集的规模和字段以天池页面的说明为准，下载前请确认它的使用许可。

这个数据集只有脱敏后的编号，没有商品名称，也没有用户的年龄、性别等属性。这决定了我们能从中得到什么、得不到什么：

| 能得到 | 得不到 |
|---|---|
| 一个用户浏览多少次才买一次 | 用户是谁、多大年纪 |
| 喜欢比较还是直接下单 | 买的具体是什么商品 |
| 活跃在什么时段 | 为什么买 |
| 类目兴趣是集中还是分散 | 对文案的偏好 |

所以要分清两层：**行为特征来自真实数据，人物设定是合成的。** 这条界线在文档和代码里都要标明。

## 第一步：从行为数据里提取行为特征

对每个用户算一组统计量：

```python
def behavior_features(events: pd.DataFrame) -> pd.DataFrame:
    g = events.groupby("user_id")
    f = pd.DataFrame({
        "pv":           g.apply(lambda d: (d.behavior == "pv").sum()),
        "buy":          g.apply(lambda d: (d.behavior == "buy").sum()),
        "cart_or_fav":  g.apply(lambda d: d.behavior.isin(["cart", "fav"]).sum()),
        "categories":   g.category_id.nunique(),
        "night_share":  g.apply(lambda d: d.hour.between(21, 24).mean()),
    })
    f["buy_per_pv"] = f.buy / f.pv.clip(lower=1)                  # 看多少次买一次
    f["hesitation"] = f.cart_or_fav / (f.buy + f.cart_or_fav).clip(lower=1)  # 加购收藏但没买的倾向
    f["focus"] = 1 / f.categories.clip(lower=1)                   # 兴趣集中程度
    return f
```

全量数据很大，抽样几万名用户就够用。

然后对这些特征做聚类，得到几种行为类型：

| 行为类型（示意） | 特征 |
|---|---|
| 果断型 | 浏览少、购买比例高、很少加购 |
| 比较型 | 同类目内浏览很多、加购收藏多、最终购买比例中等 |
| 闲逛型 | 类目分散、浏览多、几乎不买 |
| 囤货型 | 购买次数多、类目集中 |

聚成几类、每类叫什么，取决于你的数据。上表是为了说明形式。聚类用 K-means 即可，类别数取 4 到 6，选轮廓系数较好并且每类都能说出含义的那个。

## 第二步：结合商品定义目标人群

行为类型和商品无关。目标人群要结合卖点来定义，这一步交给模型，但要给它约束：

```text
商品卖点清单：{selling_points}
评价里出现的使用场景和顾虑：{review_themes}

请提出 3 到 5 类最值得触达的目标人群。每类包含：
- 名称
- 使用场景：在什么情况下会用到这个商品
- 核心动机：最在意哪一两个卖点（引用卖点编号）
- 主要顾虑：什么会让他们不买（尽量来自评价里的原话）
- 不适合的说法：对这类人应该避免强调什么

要求：各类人群的核心动机不能相同；每一类都要能在评价里找到对应的声音。
```

“每一类都要能在评价里找到对应的声音”是防止模型凭空造人群。评价里没有任何人提到运动场景，就不应该出现“户外运动人群”。

```python
@dataclass
class Segment:
    id: int
    name: str                    # 如“敏感肌人群”
    scenario: str
    motives: list[int]           # 卖点编号
    concerns: list[str]
    avoid: list[str]
    review_quotes: list[str]     # 支持这类人群存在的评价原话
    size_share: float            # 在模拟用户池中的占比
```

## 第三步：构造模拟用户池

每个模拟用户是“一类目标人群”和“一种行为类型”的组合，再加上个体差异：

```python
@dataclass
class SimUser:
    id: int
    segment_id: int              # 属于哪类目标人群（合成）
    behavior: dict               # 行为特征，从真实用户中抽样得到
    price_sensitivity: float     # 个体差异（合成）
    persona: str                 # 一段人物描述，由上述字段渲染而成
```

行为特征直接从真实数据里抽一个真实用户的统计量填进去，而不是让模型编。这样模拟用户池在“多少人爱比较、多少人只逛不买”这些分布上是有真实依据的。

人群和行为类型怎么搭配，没有真实数据可以依据，只能假设。本项目的默认做法是独立抽样，即每类人群里各种行为类型的比例都和总体一致。这是一个需要明说的简化假设。

人物描述由代码把字段渲染成文字，不让模型自由发挥：

```text
你是一位通勤上班族，夏天每天出门都会涂防晒。
你最在意：成膜快、不黏腻；不含酒精。
你担心：叠加粉底会搓泥。
你的购物习惯：会在同类商品之间反复比较，经常加入购物车后过几天才决定；对价格比较敏感。
```

用模板渲染的好处是每个模拟用户的设定都可追溯到结构化字段，归因时能按任意字段切分。

## 人群定义会在闭环里被修正

第一轮的人群定义是基于卖点和评价的推测。试投几轮之后，可能发现某类人群对所有素材都没有反应。归因环节会报告这一点，主管可以决定回到这一步，合并或者重新划分人群。

注意这里的循环论证风险：人群是模型定义的，模拟用户是按这个定义造的，再由模型扮演他们来验证这个定义。模拟环境一章会专门讨论怎样降低这个问题的影响。

## 自己动手时的检查点

1. 下载行为数据集并抽样，算出行为特征，完成聚类，为每一类写一句话描述。
2. 为你的商品生成人群定义，逐类检查能不能在评价里找到对应的原话。
3. 构造 500 个模拟用户，检查行为特征的分布和真实数据抽样的分布是否一致。
4. 在文档里写清楚：哪些字段来自真实数据，哪些是合成的，做了哪些简化假设。

## 面试常见追问

- **人群怎么分的？** 行为特征聚类加上基于卖点和评价的动机划分，两层分开讲。
- **没有真实用户数据怎么办？** 说明用了什么公开数据、能从中得到什么、得不到什么、哪些是合成的。
- **用户画像怎么设计？** 结构化字段加模板渲染，而不是自由文本；讲这样做对归因的好处。
- **人群分错了怎么发现？** 试投后某类人群整体无反应，或者两类人群对所有素材反应一致，都是信号。
