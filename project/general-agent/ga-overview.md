做完这个项目，你手里会有一个自己从零写出来的通用 Agent：在终端里它能读代码、改文件、跑命令、修 bug；换一组工具，它能接一个问题，拆成几个子问题并行去查资料，最后交回一份带引用的研究报告。两种能力用的是同一套内核。

这一章先讲清楚三件事：最后做出来的东西长什么样、为什么要这样设计、整个项目分几段走。

## 做出来是什么样

**编程模式**。在一个代码仓库里启动它，用一句话描述问题：

```text
> tests/test_cart.py 里有一条用例挂了，帮我修好

● 读取 tests/test_cart.py
● 运行 pytest tests/test_cart.py -x
  1 failed：test_discount_rounding，期望 9.99，实际 10.0
● 读取 shop/cart.py
● 修改 shop/cart.py（需要确认）
  - return round(total * rate)
  + return round(total * rate, 2)
  允许这次修改吗？[y/n] y
● 运行 pytest tests/test_cart.py -x
  5 passed

折扣金额取整时丢了小数位，已改为保留两位，5 条用例全部通过。
```

**研究模式**。给它一个开放问题：

```text
> /research 对比三种主流向量数据库在千万级数据下的写入和查询表现

● 研究计划（可修改后再开始）
  1. 各自的索引结构与写入路径
  2. 公开基准里的查询延迟与召回率
  3. 运维成本与已知限制
● 派出 3 个研究员并行查找……
  研究员 A 完成：4 个来源
  研究员 B 完成：6 个来源
  研究员 C 完成：3 个来源
● 证据是否足够：第 2 项缺少同一硬件下的对比，追加 1 个子问题
● 生成报告：report-2026-11-18.md（13 个来源，27 处引用）
```

上面两段是目标形态的示意，具体输出会随你用的模型和任务不同而变化。

## 为什么是“一套内核，两种模式”

编程助手和研究助手看上去是两个产品，拆开看却是同一组部件：

| 部件 | 编程模式里做什么 | 研究模式里做什么 |
|---|---|---|
| 执行循环 | 调模型，执行它要求的工具，把结果喂回去 | 完全相同 |
| 工具 | 读文件、写文件、改文件、跑命令、查找、搜索 | 联网搜索、读网页正文、压缩摘录 |
| 上下文管理 | 文件内容和命令输出很长，要压缩 | 网页正文更长，要压缩 |
| 权限 | 改文件和跑命令前先问人 | 访问外网前按规则放行 |
| 子任务 | 把“在仓库里找某个定义”派出去 | 把每个子问题派给一个研究员 |
| 记忆 | 记住这个仓库的约定 | 记住用户关心的方向和可信来源 |

所以项目的做法是：先把内核写扎实，再往上挂两组工具。面试时这也是最值得讲的一点，它能直接说明你理解的是 Agent 的结构，而不是某个产品的用法。

## 不用框架

整个项目不依赖 LangChain、LangGraph 这类编排框架，只用模型接口的官方 SDK 和几个基础库。原因很实际：面试官追问“框架背后在做什么”时，用过框架的人往往答不上来，自己写过一遍的人可以一直往下讲。

研究模式那一章会专门安排一节，把同样的主管加研究员结构用 LangGraph 再写一遍做对照，这样被问到框架时你也有话说。

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11 及以上 | Agent 岗位的招聘要求里最常见 |
| 模型接口 | OpenAI 兼容接口 | 国内的 DeepSeek、通义千问等都支持，换模型只改配置 |
| 终端界面 | Rich + prompt-toolkit | 流式输出、确认弹窗、历史记录都有现成支持 |
| 存储 | 文件 + SQLite | 会话记录用逐行 JSON，长期记忆用 SQLite，不需要另装服务 |
| 联网搜索 | 可替换的搜索接口 | 研究模式需要，你要自己申请一个搜索服务的密钥 |

## 三段路线

项目分三段，每一段结束都有一个能独立演示、能写进简历的成果。

| 阶段 | 章节 | 做完能演示什么 |
|---|---|---|
| 第一段：内核与编程模式 | 系统架构、执行循环、工具系统、权限、上下文管理、记忆 | 在真实仓库里修 bug 的终端编程助手 |
| 第二段：子任务与研究模式 | 子任务调度、研究模式 | 输入问题、输出带引用报告的研究助手 |
| 第三段：扩展与评测 | MCP 与技能、评测 | 接入外部工具；用数字说明它在你的任务集上表现如何 |

只做完第一段也是一个完整的项目。后两段是在同一个仓库上继续加东西，不需要推翻重来。

## 开始之前需要会什么

- 能读写 Python，知道 `async/await` 的基本用法。
- 会用命令行和 Git。
- 调用过一次大模型接口，知道消息列表和工具调用大致是什么。

如果最后一条还不熟，先读知识库里的 [Function Calling 与工具调用](../../knowledge/llm/dev/function-calling.md) 和 [Agent Run Loop、轮次与终止条件](../../knowledge/llm/agent/agent-run-loop.md)，再回来看下一章的系统架构。
