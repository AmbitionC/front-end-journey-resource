# 面经目录与知识关联

面经按「公司 → 公司部门/明确业务归属 → 帖子」组织。原文没有明确归属时放入「其他」；岗位、技术栈、候选人以前的项目不作为部门证据。岗位及原有岗位方向保留在叶子的 `role`、`roleCategory` 元信息中。部门名称在 `department` 中，与中间目录节点对应。

统一原文明示的别名和大小写，例如中交广 → 中国交易与广告、wxg → WXG。原文明写「AML / 火山方舟」时保留联合称呼，不推定更细组织。仅有依据的简称推断才归类，不将简称推断提升为全称原文明示。

部门归类覆盖全部 95 篇面经：33 篇有部门线索，62 篇归其他。叶子 `key`、`filePath` 及日期保持不变，实际 Markdown 文件仍在原路径。网站深链接使用 `/interview?activeKey=<稳定 key>`，目录分组不改变帖子身份。同一页面包含不同公司的记录时，标题、题段和知识反链明确公司归属，复用原页面，不重复建帖。

原有 938 条知识到面经的公开关联中，当前保留 873 条、65 条待核实。此前暂撤的 174 条旧未证明关联与 54 条争议关联共 228 条已逐条重新判断，恢复 164 条、继续暂撤 64 条；另撤去 1 条将一般企业 RAG 问题收窄为 ACL 专题的旧关联，改绑已有 RAG 完整流程。原先保留的 710 条中，本轮独立审阅另核对了 JUC 与企业 RAG 两例，其余 708 条没有本轮逐项语义裁决。这些数字不表示全库语义审核通过，也不表示独立面试场数。没有删除帖子，待核实关系不等于虚构题目。

相关机制可作为学习导航，但不证明原问的每个细节均已覆盖，也不把整理答案中的教学扩展当作面试官明问。

涉及错误问题绑定的帖子使用 `short-qa-v2`。未绑定问题必须以 `data-binding-status="pending_semantic_verification"` 和可见的「关联知识点待核实。」说明标注；相邻短答始终保留。已知原题关键词遮蔽使用 `pending_missing_keyword` 并保留遮蔽说明。已验证绑定仍需要有效知识 key、速读及真实反链。此格式不允许以待核实状态保留错误知识 key。

`interviewCountBasis="verified-public-posts"` 表示热度来源计数按已核对的公开帖子去重。它不是独立面试场次、轮次数或新增更新条目数。原作者的记录证明内容出处，经历和现场回答并未因此得到外部独立验证。

网站同步范围为 `interview/`、`knowledge/`、`images/`、`class/` 及明确的图片重同步清单，仓库中的管理报告不属于网站内容。来源隐藏检查须明确检查的文件与标识范围；网站资源检查不能替代公开 Git 仓库和历史提交检查。移除当前跟踪文件也不表示历史提交中的来源信息已经撤回。

合并前仍需完成最终版本独立审核；旧审核结论不覆盖后续改动。不要用新增更新条目数自动恢复暂撤关系或增加热度。
